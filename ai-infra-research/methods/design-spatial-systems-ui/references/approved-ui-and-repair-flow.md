# 已批准 UI 的增量设计与修复流程

适用：在既有技术画布中新增诊断、告警、方案选择和修复对比。基于 2026-10-16 CP-01 用户反复纠正后的规则；案例数值和 Pass 编号不作为通用事实。

## 保留定稿结构

- 用户说 approve、定稿或不要改现有 UI 时，保留框架、导航范围、图元、配色与交互模型。新增内容复用现有组件；独立副本也遵守该约束。
- 不用诊断步骤替换真实 Pass 导航，不把 Scope 对照、数值结果伪装成 Pass。无原始快照时明确证据缺失，不制造变换。
- 聚焦一个故障场景时，保留导航上下文；按用户要求将无关阶段灰显、禁用，将当前异常阶段用警告色填充圆圈。不要把展示焦点说成已证明的唯一根因。

## 图元与排版

- 此用户的系统绘图优先 fill、少用 border：用有限的中性填充层级分组；描边主要保留给选择、焦点和确有语义的边界。
- 对照方案共享列宽、行高、内边距、文字基线；Scope、存储绑定、结果采用固定对应列。嵌套图元的 CSS 不得继承方案容器的 grid-column 导致错行。
- 保留 Tensor、计算、通信、控制、存储等已批准类别编码，不因局部美化改动全局语义。
- 不添加文字阴影、光晕或装饰性厚阴影。检查共享玻璃样式与运行时注入的实际 computed style，不只追加覆盖规则。

## 一项决策用一张完整卡片

- 标题、简短问题说明、候选方案、应用动作与必要证据说明属于同一决策，应在一张完整实心卡内组织。内容分组不等于创建多个外层卡片；不要一行一张卡。
- 候选方案上下排列，用留白与轻填充选中态区分；推荐标签放在方案标题同一行。方案内部的小图不是另一套厚重卡片系统。
- 短操作说明和主动作放在同一主体卡片底部。不要额外拆出说明卡、按钮卡、页脚卡。
- 对已要求的灰色实心卡片，禁用外层 Liquid Glass 背板、blur 和描边；不要后续又回退到玻璃面板。
- 若另一个任务明确要求 blur，则只在面板真实边界内使用约 90% 不透明填充（不是 90% 透明）；禁止让全高透明 inspector 的空白区继续模糊画布。用户最新材质要求优先于 skill 的默认玻璃预设。

## 告警到修复

- 默认显示问题对象上的告警；用户选择并应用方案后才出现修复结果。不要用三个并列状态 tabs 让用户自己猜哪个是问题、哪个是修复。
- 告警贴近所属对象，跟随画布缩放平移，并避开连线路径；需要时放在对象底部。警告状态按批准色使用实心填充，不能靠文字颜色独自承担。
- 告警标签说明对象和异常，删除无助理解的 BEFORE 等阶段术语。点击入口直接进入紧凑方案选择。
- 推荐只给有证据支持的方案；无效尝试必须继续显示失败。应用已有实验记录不宣称执行了本机编译或硬件复验。

## 把对比放到方案选择

- 用户需要比较才能决策时，在第一步直接合并分析，不强制进入第二个 Diff 页面。
- 每个方案用小图同时呈现结构改动、对象绑定、验证结果。例如 scope 拆分图 + 四个独立地址填充块 + PASS/仍 FAIL。
- 突出改变与结果，删除重复的当前问题摘要、长段诊断文字与难以读懂的伪代码 +/- Diff。若用户保留源码 Diff 需求，单独提供真实、可追溯的源码差异。
- 保持事实、假设、缺失证据可区分；未知生命周期不画成已确认冲突，地址共用不直接等同于完整根因。

## 防止修正回退

修改前列出本轮要变和必须保留的约束；以最新确认结果为基线，不逐条机械叠加旧 CSS。检查最终级联和重复选择器，及时合并被替代规则。
最终浏览器验证至少覆盖：默认告警、选择两个方案、应用推荐方案、无效尝试与重置；核对卡片边界、文字阴影、对象标注遮挡、图元横排与列对齐。未验证状态如实报告。

本案例约束：CP-01 在原页面 P36 位置聚焦；其余 Pass 灰显；黄色告警条在 UB 下方；单张灰色实心方案卡；上下两个方案；分析已合入选择页，无顶部重复概览。相关实现：/Users/yin/PyPTO3-main/Design/pass-error-cases/。

## 直线优先的连线路由

先用真实图元尺寸对齐节点与端口，再决定路径。同排数据流优先水平直线；上下输入端口对齐时用竖直直线。禁止用微小折线补偿节点中心或 style box 与实际 glyph 的尺寸误差。只有真实障碍、分支或跨组关系才增加必要折点；不得为统一路由而强制所有边走正交折线。拖动或方向切换后重算端口。验收需放大检查局部连线，并核对实际 glyph/Handle 坐标；总览截图和构建通过不足以证明路径合理。
