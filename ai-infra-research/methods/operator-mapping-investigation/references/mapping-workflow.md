# 算子映射调查

用于验证具体索引、布局与访存假设。通用能力是“逻辑元素 → 源地址 → 搬运后布局 → 计算输入 → 源码”的可追踪关系；不以自动发现所有错误或瓶颈为目标。

## 接收输入与确定范围

先从会话和仓库读取：源码仓库及固定 revision、算子和生效分支、代表用例的 shape / dtype / axes / stride，以及用户要核查的问题。数据缺失时先完成独立分析，再只询问会阻塞映射的字段；不要要求用户预先知道 Pattern 或自己选图元。

区分数学定义、Host 参数构造、Kernel 访问表达式、API 约束与运行观测。发现上游参数不确定时，后续精确映射带上具体条件，不把预期路径当成确认执行路径。源码与数学定义不一致时保留两套集合，不为画面闭合而修正实现。

## 资产与实现入口

领域建模与图元选择分开；映射确定后交给 ai-infra-glyphs 选择正式图元。若 AI_Infra checkout 可读，可检查：

- `ai-infra-research/prototypes/logsumexp-case5/model.js`：纯模型、稳定对象与证据导出。
- 同目录 `page.html` / `build.py`：画布、选择、源码窗口与独立 HTML 构建方式。
- `verify.cjs`：该案例的独立参考与覆盖检查。

这些是固定案例源码，不是通用算子 API；安装 Skill ZIP 不会自动附带该原型。找不到 checkout 时说明可复用资源范围，使用随包图元，或请求仓库路径；不要声称已有通用工具接口。没有用户授权不下载环境、不安装 CANN、不租硬件、不修改被分析算子。

## 建模与输出

用独立于 DOM 的模型表达配置、对象 ID、逻辑成员、地址及单位、请求槽、目标槽、参与计算标记、写回与源码引用。布局层只消费模型，不再写一套索引公式。未知关系保留为未知；部分不支持不阻止已确认部分的检查。

先做一条普通对象链和一条有代表性的边界链，再扩展全集。边界可以是尾块、mask、padding、对齐或间接索引，并非每个实现都有尾块；不要固定用 8／7 列或默认把额外请求标成错误。数据角色、选择和调查范围分别编码。

每个可选择对象带精确数值、源码文件/行号/revision、推导条件和待确认项。交接内容包括当前配置、选择、相关参数、证据和用户问题，并可预览、复制。只建设任务要求的交接，不默认加入 MCP 或 IDE 插件。

## 不支持的语义

遇到未知 DataCopy / Gather 等 API、动态地址或不确定 Host 参数时，指出缺少哪个定义或证据、哪些下游关系受影响；可继续呈现数学集合与已知地址。下一步是核对对应版本文档、作者说明或最小实验，不自行猜硬件行为。没有 profiling 不能推断实测瓶颈、时长或加速比。

## 可复用验收

- 依据独立计算检查逻辑集合、地址、单位、覆盖、遗漏和重复；分开统计请求、消费与写回，说明重复是否有算法用途。
- 校验普通与边界对象，导出内容随选择和问题变化；源码位置来自固定版本。
- 验证换配置时，从配置到分组、布局与文案是否真正重算。仅替换标题或 shape 文本不算参数化。
- 声称支持同类配置前，至少再用一个不同边界的合法配置验证同一适配器；未验证时交付明确的固定案例。迁移第二个实现时重新确认 API 与布局规则，不沿用第一个实现的公式。
- 数值 CPU 参考、静态模型检查、真实渲染、设备运行分别记录，任何一层通过不代替另一层。

## 最小调用示例

用户可说：“我怀疑这个非末轴归约的尾块搬运范围。分析仓库中的 LogSumExp Case5，不改算子；复用 AI_Infra 调查视图，让我选择一个输出核对输入、搬运和源码。”

agent 应固定版本，建立并验证集合与访问映射，复用画布和图元，交付可打开 HTML、模型与验证记录。用户选择后复制问题与证据，agent 回到源码/API 继续核查，先给可核查结论和最小验证方案，再按授权决定是否改代码。
