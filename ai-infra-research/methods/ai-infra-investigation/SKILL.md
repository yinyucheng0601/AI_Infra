# AI Infra 可视化总 workflow

这是一个调度入口，不是通用诊断引擎，也不自带 API 语义解析器。用户只需描述要可视化的内容与目标，可提供模型、代码、配置、数据、文档或仓库，不需要记住 Skill 或 Pattern 名称。理解机制、浏览架构、配置部署、比较实验与调查问题都是有效目标；不要求先提出故障假设。

## 开始前

先读目标项目 AGENTS.md 与当前产物。确认任务确实需要结构、映射、比较或运行关系视图；若文字/查询足以回答，直接给证据，不强制画图。先在会话、源码与可用资源中补全输入，仅询问阻塞项。默认不改被分析算子，不安装硬件环境，不发布外部内容；按本次授权执行。

子 Skill 在 AI_Infra checkout 的 `ai-infra-research/methods/<name>/SKILL.md`，或本次环境安装目录。读取当前可用版本，不假设自动安装。完整组合包包含总入口和五个同级能力目录；单装本目录只获得调度指令。缺少资源时说明可完成的范围，不能用课程报告替代调查工具。

## 领域路由：覆盖全流程，按证据选择路径

| 任务 | 优先组织的对象与关系 | 分析与表达入口 |
|---|---|---|
| 模型架构与计算机制 | 模型→层→模块→OP，张量、权重、状态与复用 | llm-compute-diagrams；模型源码/config 提取器；模型架构与 Layer Atlas Pattern |
| 训练 | 前向/反向、梯度、优化器状态、重计算、并行组、分片与内存 | llm-compute-diagrams；训练 Layer/Rank/内存与通信 Pattern |
| 推理与 Serving | 请求、Prefill/Decode、调度批次、KV cache、Host/Device | inference / traceview 参考；请求泳道、模型图与状态视图 |
| Rank、服务器、集群部署 | 逻辑并行组→Rank→设备→节点/服务器→机柜，通信与存储归属 | parallelism 参考；Rank Atlas、物理布局、硬件 Explorer/Anatomy |
| 算子开发 | 索引、布局、tiling、buffer、Task/Core 与同步 | operator-mapping-investigation；已有算子调查 Pattern；所需 API/审计工具 |
| 编译与 IR / Pass | 前后快照、对象身份、变换、控制作用域、内存绑定 | compiler-objects 参考；Pass Field、Memory Inspector、诊断 Pattern |
| 性能调优 | 目标指标、配置、实现版本、测量样本、退化、瓶颈候选与方案验证 | profiling/实验分析器；RSFA 比较、请求/多核泳道及相关领域 Pattern |

外部工具的支持范围只约束该工具，不约束本 workflow。不得因某个 CANNBot skill 限定芯片、框架或算子类型，就拒绝其他 AI Infra 场景或停止页面生成。先确认用户是否需要该项估算/仿真，再核对工具条件；不匹配时跳过该工具，继续源码、配置、已有测量数据或可确认机制的分析与可视化。报告缺口时必须点名受限工具与受影响步骤，不笼统称“本 skill 仅支持”。例如某版本 ops-theoretical-performance-estimation 的 Ascend950 / DAV_3510 RegBase 纯 Vector 限制，仅适用于其标定模型，不能限制模型架构、训练、推理、部署或其他硬件的可视化，也不能移用该模型估算不支持的硬件。

这是任务路由范围，不表示已经实现各框架的自动适配器。优先复用项目已有解析器和 Pattern；遇到不支持的 IR、trace 或 API，列出缺口并降到可确认范围。源码调查模式不继承讲解的封面/分页，用户要求讲解时可以保留渐进阅读。

## 先选择完整 Pattern，再选图元

先读 [全域 Pattern 路由](references/pattern-routing.md)，检索 `catalog/assets.json` 中全部相关资产并打开实际页面入口、模型和交互实现。Pattern 不限于图例库：模型层叠、Rank/物理部署、机柜、时间轴和实验比较都是可复用能力。优先复用任务语义、布局算法、导航与选择机制，再由 ai-infra-glyphs 补齐对象的正式外观；不能仅取几个 Tensor/OP 后另造整套交互。不要将示例 shape、模型、硬件数量或内置数据当成新任务事实。

## 实现入口：先建立表达约定

实现前用简短记录明确六项内容，已有答案从会话、证据和定稿参考中提取，不新增强制审批：本轮要回答的问题；主图与辅助图各自职责；坐标及尺度承诺；对象身份与关联关系；类别色、数据角色色和选择态含义；默认、选择、布局切换与退出恢复的状态转换。记录到产物的设计/验证说明中，不将这份内部约定作为常驻解释堆到页面上。

按问题选择视图，不按关键词拼装全部 Pattern。比较重读成本可用方案对照；调查何时保留、释放和再次使用，可用源码顺序泳道与生命周期联动；查执行归属可用硬件定位。未知逐事件时长时，源码步骤轴不得承诺真实耗时或重叠。硬件图是否适合作为主图取决于问题，不能因参考存在就用作底图。

先完成可操作骨架，走通默认、具体对象选择、相关视图联动，以及适用时的分屏和退出恢复，再接完整数据与视觉精修。浮层用于临时检查，并排视图用于比较；进入分屏可以重新安排视口，退出应恢复进入前视角。默认去色、关联染色是可选策略，通用要求是颜色含义明确且跨视图一致。

## 按需执行的阶段

### 调查工具的界面约束

索引、布局、搬运等对象调查工具默认采用全视口无限画布作为主体，身份、配置、导航与缩放作为独立控制组件，证据与源码作为按需打开的浮层。页面滚动中的图表区域、常驻双栏检查器和“大标题—指标—图表—页尾”骨架不能替代这种工作台。比较图可以使用共享坐标或并列布局，仍须遵循用户已经确认的宿主布局；讲解报告和用户明确指定的其他页面类型按其任务处理。

实现前读取当前已定稿的同类页面，明确复用其画布、控制、检查器及视角保持机制。AI_Infra 内算子调查参考为 `prototypes/logsumexp-case5/page.html`；来源不可用时按 Spatial Systems UI 建立等价交互，不假装已复用。复用界面结构与交互，领域公式、具体坐标和案例数据重新建立。

**Let layout explain itself。** 用位置、邻近、分组、尺度和选择后的关系线表达结构。保留对象名、坐标、数值、单位及影响判断的必要前提；删除重复标题、副标题、流程口号和解释可见关系的常驻标签。补充说明进入按需详情，不用文字填补布局缺陷。

| 阶段 | 读取的 Skill | 交付给下一层 |
|---|---|---|
| 1 · 组织领域关系 | 按上表选择领域 Skill | 模型/事件/映射、对象 ID、来源、假设与验证 |
| 2 · 复用 Pattern 与图元 | 总入口检索完整 Pattern；ai-infra-glyphs 接入基础对象 | Pattern 源入口、复用机制、模型适配及类型/variant/renderer 来源 |
| 3 · 组织证据 | observability-design-style | 选择路径、检查器层级、交接内容 |
| 4 · 完成界面 | design-spatial-systems-ui | 可读画布、选择联动、面板与缩放 |
| 5 · 联合核查 | 各层按职责 | 实际交付产物及分层验证记录 |

这是同一个 agent 可顺序完成的工作流，不要求创建子 agent。已有模型、图元或定稿界面直接复用，只运行受任务影响的阶段。仅做映射分析停在阶段 1；仅调整面板不重新推导领域模型。

## 交接与冲突

按 [任务契约](references/task-contract.md) 共享配置、对象和证据，避免各层再写一套索引。用户要求与项目规则优先；领域层决定集合/地址/关系，正式图例库决定图元内部结构，证据工作台决定信息组织，Systems UI 决定外围布局与材质。旧工作台规范中的外观规则不覆盖当前已确认 UI，宿主 CSS 不覆盖 Tensor 标签或 OP 图标。

先按任务完成代表性操作链，再扩展：模型检查层级与分支，训练检查状态/分片，部署检查归属/并行组，运行检查事件/时间，比较检查口径/退化，算子检查普通与边界对象。不要把 Case05 的 8／7 列、固定轴或历史失败记录变成工具的固定中心。新 API 先确认语义；没有设备数据不画实测时间或宣布性能根因。

证据和适配器足够时，主动生成可定位的核查候选，连接对象、差异、源码与下一步问题；保留开发者自行选对象与编辑问题的入口。领域层分别报告模型差异、源码参数差异和设备观测，不把候选升级为设备故障。

多个案例按真实任务或数据关系组织导航。共同参与一次试验不构成计算链或同一工具的子视图；独立案例由目录入口组织，不在业务控件中暗示不存在的关联。

## 交付与能力声明

先验收界面骨架，再验收局部精修：默认视图须由数据对象占据主舞台；所选 Pattern 需要的拖动、缩放、fit、层级导航或播放真实可用；选择及开关检查浮层不重置视角或挤压主体；显式进入并排比较可调整视口，退出恢复原视角。暂时忽略解释性文字，检查结构与关联是否仍清楚。不满足用户确认的空间工作台布局，或依赖常驻解释才能读懂关系时，设计验收记为失败，不能用模型正确、按钮可用、无裁切或对比度通过替代。记录参考页面、实际复用机制、浏览器代表状态和未验证项。

交付前按 [联合操作路径验收](references/journey-review.md) 走通从默认视图到核查、证据、导出和返回的代表路径；不以局部截图或测试数量替代完整路径验收。

交付独立 HTML 或项目要求的界面、独立模型、来源与验证记录；按任务提供深入详情、配置比较或继续调查入口，不为没有调查需求的浏览工具添加核查面板。检查交付文件而非旧工作副本；分开报告模型、CPU 数值、图元、交互/视觉和设备验证。声称复用前验证新配置或第二实现；没有做就注明固定案例。

第一次试用与 prompt 见 [使用示例](references/first-task.md)。AI_Infra 中 Case05 是集成参考而非通用插件；ZIP 不附带原型源码，复用它需 checkout。用户未要求时不修改 catalog、安装副本或远端。

## 页面内教程入口

新生成的计算可视化页面须提供按需打开的教程模块，入口放在 info / 帮助中，使用居中窗口，不占主体画布。按“价值 → 使用 → 扩展”组织，方法与实现说明仅在有助于使用时补充；调用 prompt 与带选择继续调查放入“使用”；方法放在最后。内容必须对应当前案例、实际使用的 Skill 和能力边界，不照搬 Case05 公式或结论。外部工具的增益须具体到新增的数据、可执行模型及验证资产，区分 agent 能自行推导的内容与必须由标定、测量或外部记录提供的输入；不以实现分工替代能力说明。prompt 代码块右上角提供有可访问名称的复制图标及复制失败反馈。复用参考 `prototypes/logsumexp-case5/page.html` 的 usageWindow，或 `prototypes/compute-investigation-trial/tutorial.html`；总 workflow 介绍以当前版本为准。验收入口、关闭、复制与正文可读性，打开教程不重置画布选择或视角。


## 跨页面一致性交付自检

- 教程：新页面具备按需教程入口，按“价值 → 使用 → 扩展”组织，方法与实现说明仅在有助于使用时补充，内容对应当前案例；代码块有复制图标、可访问名称及成功/失败反馈。打开和关闭教程保持选择与视角。
- 右上角 icon button：优先复用当前工作台的统一 SVG 图标、尺寸、间距、材质和功能顺序（核查 → 当前选择 → 源码/原始数据 → Info）；同功能跨页面保持一致。业务不需要时省略，不放无效占位或伪造核查功能。
- Hover tip：所有 UI 控件含动态生成控件、菜单选项、输入、关闭、复制及画布可交互对象都有功能提示，并能由键盘聚焦触发。每个控件只用一套 tooltip；自定义提示不叠加原生 title，文字随配置和状态更新。
- 修改共享模板后检查 prototype 下所有实际交付页及已收录副本；区分模板、别名与最终入口，核对源模板重建后仍一致。记录覆盖页面、业务例外、检查方式和未验证项，不以静态扫描替代实际视觉验收。

## 扫描候选与调查收敛

接入静态审计等外部分析器时，优先增强已有对象视图，不另建脱离 Tensor、Task 与源码的报告。读取 [候选复核与版本](references/candidate-review.md)，约束扫描、调查、复核写回与演示状态；不因本案例接入 CANNBot 就默认所有任务都需要它。

仓库更新、ZIP 重新打包与本机安装是不同动作，不宣称自动同步。每次新任务使用本项目 skill 时读取当前文件，并确认实际路径；长会话修改了相关 skill 后，主动重读变更段。优先读取本 checkout 的 `methods/`，不要用已加载的旧文本或旧安装副本冒充最新版本。

## 交互高亮与语义颜色

交互高亮不默认使用绿色。先读取宿主已确认的 selection / highlight token；没有约定时使用中性近白填充与深色文字。绿色仅用于已确认的资源类别、成功、健康、已排除状态或正式图元的数据角色，不得从示例 OP、Tensor 或绿色状态胶囊推导出全局 accent。选中、关联、hover 与状态色分别定义；保留图元原有语义，不把所有相关对象染绿。
