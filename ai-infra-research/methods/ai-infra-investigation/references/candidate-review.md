# 候选复核与版本

适用于将静态扫描候选接入现有计算调查界面的任务。

- 保留原始扫描输出，复核作为独立字段追加：稳定候选 ID、待复核 / 已排除 / 仍需验证、理由、源码区间、revision/hash、剩余证据、是否重扫及设备验证。不得用复核结论覆盖原始结果，也不把“已排除具体指控”扩大为整体正确。
- agent 复核应追查调用条件、提前退出、调用方及同文件 helper，检查相应 Set/Wait 的方向、event ID 与路径是否一致。仅凭扫描器修复提示或图中缺边不足以认定故障。引用源码已足够时不堆叠同义免责声明。
- 核查列表是稳定调查任务，不随当前 shape 缩减；每项绑定有依据的配置、Task 和步骤，点击候选再跳转。当前配置内可达时原地定位；跨配置时先提示当前配置、目标配置和切换原因；无可达绑定时查看固定版本源码。不可达或不能关联当前视图的项不伪造绑定；可从主列表隐藏，但原始记录和导出须保留，并明确可见项与原始总数的区别。
- 真实复核结果可直接呈现；演示“继续调查 → 复核返回”的过程时，初始应为待复核，显式操作后才揭示预设结论，不伪装成即时调用。回放按钮用单一 hover/focus tip 说明预设行为。完成后优先展示结论与依据，继续追查可收起；复核过程不改变扫描事实。
- 本例的绿色胶囊表示已排除，其他状态遵循项目语义。候选、当前选择、复核状态与导出使用同一对象；切换配置不丢失复核记录。
- 执行与判断分别维护。成功但证据不足时追加“仍需验证”和具体缺口；执行失败只更新执行状态与重试入口。

## 代表案例

`sync-1` 是 Unpack 的同步核查候选。静态扫描提示核对固定版本源码 L430 附近搬出前的同步。扫描提供待核查线索；源码复核要核对配对方向、event ID、适用路径和证据缺口。

| 交接 | 本例约定与组件绑定 |
|---|---|
| 定位 | 候选列表点选 `sync-1`，画布定位有证据支持的配置、Task 与搬出步骤，按上节规则提示跨配置或打开源码。 |
| 核查 | Inspector 按同一候选 ID 展示原始疑点、Set / Wait 源码、调用条件、event ID 配对依据及剩余缺口。 |
| 继续调查 | Action 保存发起时的 case、候选 ID、配置、Task 与步骤、revision、证据引用、问题和未确认项。 |
| 归档与更新 | 按发起上下文归档，当前选择或配置变化不改变归属。结果须匹配身份与适用范围，且证据充分，才追加复核结论。 |

验收走通「点选 → 定位 → 核查 → 继续调查 → 查看返回」，确认候选 ID 贯穿列表、画布、Inspector、Action 和归档。分别检查四种返回：

| 返回 | 通过条件 |
|---|---|
| 匹配且证据充分 | 向发起候选追加有证据的复核判断，原始扫描保留。 |
| 上下文匹配但证据不足 | 显示“仍需验证”、缺口和下一步。 |
| 执行失败 | 保留原判断与扫描，只更新执行反馈并提供适用的重试入口。 |
| 上下文不匹配 | 按发起记录留档，提示对象、版本或适用范围差异，禁止更新候选结论。 |

可复用 checkout 中的 `prototypes/compute-investigation-trial/unpack.html` 和 `verify-sync.cjs`。现有回放在预览与导出的 `reviewArchive` 中保留发起记录、返回记录、执行状态和已采用或未采用的复核材料。仅以发起 case、候选、配置和 revision 对应的记录显示复核判断。脚本覆盖四种返回、切换选择和配置、重复与迟到返回。视觉效果、重跑扫描、设备和真实 Agent 接入另行验收。

## Runtime 接入说明

Runtime 执行调查，宿主负责事件传输和重试，呈现语义层按契约归一化事件并绑定反馈。把用户操作及其发起上下文传给 Runtime，按请求 ID 关联返回。更新前核对 case、候选、配置、版本和活跃请求；迟到或重复返回可留档，不能覆盖更新的调查。区分执行进度、用户选择和工程判断。静态回放使用相同的交接和界面反馈，无需接入真实 Runtime。

更新 skill 后重新构建只会更新仓库交付包。复制安装需另行同步，符号链接读取其当前目标；本轮究竟读取了哪份文件必须现场核对，不假定环境自动重载。不要擅自重新安装或改变用户的安装策略。
