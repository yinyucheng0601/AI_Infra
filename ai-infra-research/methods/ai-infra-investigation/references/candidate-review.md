# 候选复核与版本

适用于将静态扫描候选接入现有计算调查界面的任务。

- 保留原始扫描输出，复核作为独立字段追加：稳定候选 ID、待复核 / 已排除 / 仍需验证、理由、源码区间、revision/hash、剩余证据、是否重扫及设备验证。不得用复核结论覆盖原始结果，也不把“已排除具体指控”扩大为整体正确。
- agent 复核应追查调用条件、提前退出、调用方及同文件 helper，检查相应 Set/Wait 的方向、event ID 与路径是否一致。仅凭扫描器修复提示或图中缺边不足以认定故障。引用源码已足够时不堆叠同义免责声明。
- 核查列表是稳定调查任务，不随当前 shape 缩减；每项绑定有依据的配置、Task 和步骤，点击候选再跳转。不可达或不能关联当前视图的项不伪造绑定；可从主列表隐藏，但原始记录和导出须保留，并明确可见项与原始总数的区别。
- 真实复核结果可直接呈现；演示“继续调查 → 复核返回”的过程时，初始应为待复核，显式操作后才揭示预设结论，不伪装成即时调用。模拟按钮用单一 hover/focus tip 说明预设行为。完成后优先展示结论与依据，继续追查可收起；复核过程不改变扫描事实。
- 本例的绿色胶囊表示已排除，其他状态遵循项目语义。候选、当前选择、复核状态与导出使用同一对象；切换配置不丢失复核记录。
- 教程说明外部 skill 的具体名称、实际执行脚本、相对原有能力的提升、适配器负责的绑定，以及未实现的自动分析/设备验证。扫描调用顺序不可冒充真实时间线。

更新 skill 后重新构建只会更新仓库交付包。复制安装需另行同步，符号链接读取其当前目标；本轮究竟读取了哪份文件必须现场核对，不假定环境自动重载。不要擅自重新安装或改变用户的安装策略。
