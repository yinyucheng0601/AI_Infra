# Traceview 泳道与模型上下文

先分开「结构聚合」与「时间聚合」。模型结构可按 Layer → 子层 → 模块/算子组织；执行事件按实际 schema 中的 step、microbatch、前反向、stage、rank、stream、时间等维度组织。这些维度不一定形成唯一严格父子树，按数据是否支持展开或过滤。

同一个模块可对应多次执行事件；融合算子、通信事件或重计算又可能跨越、重复或改变模型结构映射。按稳定 ID、trace 关联字段、源码/编译映射建立关联；仅凭时间邻近或名字相似推测的关系应标为推断。

| 视图 | 应表达 | 避免混淆 |
|---|---|---|
| 模型结构图 | 计算依赖、层与模块边界 | 纵向位置不等于执行时刻 |
| 泳道事件 | 开始、结束、持续时间、执行载体 | 条宽不是 tensor 大小 |
| 聚合条 | 子事件覆盖范围或统计量 | elapsed、union 与 sum 口径必须说明 |
| 矩阵观测 | 某次执行对应的张量及指标 | 缺失观测不补成实际数值 |

让读者先理解单 rank 单微批次事件，再展开微批次、stage/rank 与跨设备通信；层级名称由 trace 数据决定，不硬套固定顺序。没有 trace 时可制作明确标注的教学数据，不声称发现实际异常。

交互可从事件选择联动模型节点和张量，再看相关上下游、其他 rank 与同步条件。区分「事件联动定位」和「性能诊断」：能定位 MoE 模块，不等于证明耗时异常源于专家负载失衡。

分析气泡或等待时保留多种候选原因，例如依赖未就绪、通信阻塞、负载不均或调度间隙；用可见证据逐步排查。清楚区分观测、假设、验证所需数据与后续调优方向。
