# 模型推理

从任务范围确定讲解：自回归生成、批处理服务、prefill/decode、KV cache、推理并行或具体优化。以一条可追踪的请求为主线，区分请求、序列、token 位置和服务端 batch。

推荐先说明 token ID → embedding/位置处理 → 层栈 → 最终隐藏向量 → LM Head/logits → 解码选择，然后对照 prefill 与 decode。prefill 处理提示词，decode 逐步计算新增位置并复用历史信息；是否缓存、缓存结构和注意力窗口以模型实现为准。

将 KV cache 画为带位置和层标签的状态存储，与每步激活及权重区分。K/V 随请求增长或窗口变化，缓存不是训练梯度，也不一定缓存全部中间激活。新增 token 的计算会读取相关历史缓存；用箭头区分读取、追加与可能的回收。

讲连续批处理、分页 KV、推测解码、量化或 prefill/decode 分离时，每次只增加理解该优化所需的状态及调度条件。示意 token 概率、耗时和缓存容量均标注为示例。吞吐、首 token 延迟、单 token 延迟、总体延迟使用明确口径；精度、性能或成本比较需要来源。
