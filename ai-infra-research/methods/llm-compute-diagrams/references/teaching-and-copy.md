# 渐进讲解与文字

## 每页承担一个可回答的问题

图解说明对象和关系，正文解释为什么如此，以及结果对下一步计算有什么意义。先说明读者当前正在观察哪一个层级、哪个输入和哪个阶段，再引入内部细节。完整总览是前面图元的汇合，应能逐项对应；不要在最后突然引入大量未解释符号。

可用「整体任务 → 输入和图元 → 单个机制 → 机制组合 → 扩展及限制 → 完整总览」组织新主题，按知识依赖调整顺序。结构视图与时间视图可分别成组，再讲它们如何关联，不把两种父子层级硬合成一棵树。

## 标题和段落

优先采用准确、完整的主谓或疑问结构。定义技术名词后再使用缩写。正文用完整段落，通常每页 2–3 段；按信息量增减，不逐句拆行，也不以堆叠结论代替推导。数学符号只保留解释机制所需的部分，给出符号对象和 shape。

| 避免 | 改写方向 |
|---|---|
| 四路表示，共享一次子层计算 | 四路残差流共用一个计算分支 |
| 四路不是四个头、四个 token 或四个模型 | 每个 token 保留四个 H 维特征向量；读取后送入同一个计算分支 |
| 梯度不会替代前向数据流 | 反向传播计算梯度，优化器据此更新权重 |
| 不能简单说成免费提升四倍能力 | 扩展了残差状态的容量，也增加映射、访存和相关通信开销 |
| 关键边界不是分支结束 | 子层以残差相加后的结果作为输出 |

这些是写法示例，不是要求把所有否定句删除。因果掩码、数据缺失、机制适用边界或用户确有的误解仍需明确解释；先给正面模型，再简短对照。

「表示」作动词和名词容易混淆时，改用「特征向量」「残差状态」「激活矩阵」。对「主流表示」「某节点的结果」等模糊指代，写明 X、Y、分支输出或子层输出。

不要在面向读者的正文中反复叙述制作过程、风格选择或实现细节。示意网格、抽样数据和未展开项的说明集中进 info；会改变结论的具体假设保留在正文及图注中。

## 来源与准确性

让正文中的定义、图内标签、点击释义和公式互相一致。标明模型范围，例如 decoder-only Pre-Norm，避免将其冒充所有 Transformer 的唯一架构。模型版本、数值、并行配置和性能结论要有来源或清楚标为示例。参考 HTML 的事实只服务于它原来的教学范围。

## 技术概念与专业表达

技术图解采用准确、克制的专业语言，用明确的对象、机制、条件与结果组织解释。通俗表达可以帮助理解，但不能替代技术定义，或产生源码与文档中不存在的对象分类。

- 优先使用源码、官方文档或原始论文中的术语。必要的中文译名在首次出现时与原名对应；教学中自定义的简称应明确其含义，不能作为实现中已有的类型或机制介绍。
- 标题与章节导航概括技术内容，不描述“把对象连起来”等绘图动作。“接用”“守住”“空档”等比喻不用于承担生命周期、复用条件或并发约束的定义。
- 直接解释关系含义、成立条件及适用范围。例如写“无向边表示两值的生命周期重叠”，而非只写“它没有执行方向”。图形是否有箭头，不能代替关系的技术定义。
- 区分候选条件、完整安全条件和已经观测到的结果。满足一项复用条件不能直接写成“可以复用”；已见最终地址也不能直接断言由某个 Pass 首次产生该结果。
- 教学关系图标明构造依据。根据示例绘制的图不冒充编译器导出、自动解析结果或实际 trace；具体实现结论注明版本或配置边界。

| 需要修正的表达 | 改写方向 |
| --- | --- |
| 把同时需要保留的值连起来 | 生命周期干涉限制缓冲区复用 |
| 它没有执行方向 | 无向边表示两值之间的生命周期干涉关系 |
| 定义之后，要守住每一次读取 | 最后一次使用位置影响复用条件 |
| A 和 C 接用一块存储 | 满足复用约束时，A 与 C 可共享 MemRef |
| 程序序里的空档仍被占用 | 流水并发与别名关系影响复用判定 |

交付前按同一术语表检查导航、标题、正文、图注、公式和点击释义。发现概念混用时，应修正其定义、图中关系与适用条件，不能只替换成更正式的同义词。编译与内存图解另见 [编译概念区分](compiler-objects.md#编译与内存概念的区分)。
