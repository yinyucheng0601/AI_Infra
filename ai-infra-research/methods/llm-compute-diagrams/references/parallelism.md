# 多卡并行与通信

先确定「谁持有什么、谁计算什么、何时与谁交换什么」。分别画逻辑模型、张量分片、并行组和执行时间，必要时联动。rank 是进程标识，不能在所有部署中直接等同设备；说明所用映射假设。

| 策略 | 适合突出的问题 | 需要核验的边界 |
|---|---|---|
| DP | 样本如何分给模型副本，梯度如何同步 | 普通 DDP 与 ZeRO/FSDP 的状态分片不同 |
| TP | 一个算子的张量维度如何分片 | row/column parallel、聚合位置依赖具体实现 |
| PP | 不同层放在哪些 stage，微批次如何推进 | 前反向调度、边界激活、P2P 与气泡 |
| CP/SP | 序列相关数据如何分摊 | 两者命名及通信方式依框架而异 |
| EP | 专家分布及 token 分发 | 专家组与 DP/TP 组可能重叠，专家内部可再切分 |

先选择一组可自洽的小规模示例，用同一 token、microbatch 或 tensor ID 跨页追踪。根据框架 rank 布局验证 World Size 和各组大小。不要把所有并行倍率都独立相乘；例如 EP 往往在既有维度内重组进程组，不能默认加入 DP 的分母。

通信图标明参与组、集合操作、载荷、shape 和前后分片状态。区分 AllReduce、AllGather、ReduceScatter、All-to-All 与 P2P，示意箭头不代表实测链路或带宽。需要时间轴时用独立事件条，并说明计算通信是否存在数据依赖、异步重叠以及等待条件。

示意通信量可以据 shape 和 dtype 估算并展示公式，但实际链路流量和时间取决于算法、拓扑、实现及运行环境。不同 rank 的执行事件不能仅凭图面位置判为同时发生。

视觉编码采用 [已确认的并行切分与 MoE 图例](visual-system.md#并行切分与-moe-图例用户确认)：DP 绿、TP 蓝紫、SP 浅蓝、CP 青绿、PP 玫紫、EP／MoE 橙。切分色用于维度与关系，张量填色继续表达权重、梯度和激活等类型。
