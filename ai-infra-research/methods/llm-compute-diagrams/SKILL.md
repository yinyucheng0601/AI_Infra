# 大模型计算图解

把计算机制组织成读者可以逐页理解、操作并最终读懂完整结构的网页。面向具备产品或设计经验、正在建立 AI infra 概念体系的读者。默认使用中文专业解释、深色矩阵图元和离线单文件 HTML；用户本次要求优先。

## 先确定要解释的关系

从用户的问题中识别具体认知缺口，明确本次范围：模型计算结构、张量及形状、设备部署、运行事件，或几者之间的映射。以给定材料的当前内容为依据；修改现有网页时优先使用用户选中的最新文件，而非本技能示例。

技术内容分为通用机制、具体实现、教学示例三种证据层级。涉及模型配置、论文新机制、框架并行组或实际 trace 时，核对官方文档、源码或原始论文，并把来源链接放在相关解释旁。材料不足时标注示例及假设；不要将假定的 rank、shape、耗时或通信关系写成观测事实。

按主题读取相关参考，避免把所有主题知识都塞入每次任务：

- 视觉、网页交互或图元实现：读取 [visual-system.md](references/visual-system.md)。
- 标题、正文、知识递进：读取 [teaching-and-copy.md](references/teaching-and-copy.md)。
- Attention、FFN、Dense、MoE、普通残差或 mHC：读取 [sublayers.md](references/sublayers.md)。
- 多卡训练、并行组和通信：读取 [parallelism.md](references/parallelism.md)。
- 生成、prefill、decode、KV cache：读取 [inference.md](references/inference.md)。
- 模型结构与 trace、泳道层级、异常联动：读取 [traceview.md](references/traceview.md)。

## 组织一条渐进的讲解线

先在内部写出每页的「读者问题—核心结论—图中变化—解释—来源或假设」。按依赖关系排序，不机械照抄用户列出的疑问顺序；页数取决于主题，不固定为 11 页。

从完整计算任务的位置关系切入，再引入必要的图元与中间状态，逐步增加计算、数据和设备细节，最后汇合为可交互的完整图。普通机制与其扩展连续讲解，例如普通残差 → 多路残差 → mHC 混合约束，Dense FFN → 路由 → MoE → 两者对照。

每页图解旁设独立文字区域，写清操作对象、计算方式、输入输出及其意义。保持先定义、后机制、再适用范围的次序，避免由一连串「不是」「不能」组成解释。用明确的名词短语，如「四路残差流共用一个计算分支」，替代「四路表示，共享一次子层计算」这种主语不清的标题。

## 用统一图元承载准确语义

复用图元的含义与样式，不强迫所有主题使用同一种图形。用矩阵表达张量，用节点和箭头表达计算依赖，用设备容器表达部署，用泳道事件表达时间。结构包含、张量分片与执行事件采用不同关系类型，关联时显式说明映射依据。

蓝色用于激活数据，金色用于参数，紫色用于梯度；每页保持一致。通信事件、等待区间和设备标识另设明确标记，避免借用紫色表示所有反向以外的事情。注意力系数、路由系数和运行时连接系数应标为中间计算结果，不能仅因其参与加权就画成固定参数。

新建或扩展网页前，必须读取 visual-system.md 的图元字典和 Add 实现，并查看参考 HTML 的图元页（VISUAL VOCABULARY，含封面时为第三页）。既有语义复用既有图元：逐元素 Add 使用圆形加号，逐元素乘法及标量广播乘法使用大圆圈内的乘号 ×（读取 visual-system.md 的 Multiply 规范），Norm、Attention、FFN 等计算模块使用中灰填充的大圆角矩形与居中白色粗体文字；不要将所有可点击节点统一套成矩形卡片。

张量小格统一为正方形，真实 shape 通过文字标注。示意网格的格数与亮度不承诺真实值；需要真实数值时另行标注。随视图缩放保持横纵比例一致。所有关键输入、分支结果、残差合并结果、参数、梯度和必要的数据边界都应可解释。

## 复用参考，但不继承旧内容

[reference-guide.html](assets/reference-guide.html) 是用户确认过的完整离线示例，包含封面、底部文字 step 导航、右上角 info、图元释义、正方形矩阵和可缩放总览。它是视觉及交互参考，不是事实来源，也不是每个新主题的固定课程结构。

新建系列页面时可提取示例的 CSS、矩阵和连线函数、info、导航及缩放实现，先整理成统一的数据结构再扩展。示例的原始页码、重排数组、diagramId、条件分支和固定总览尺寸属于该案例；移植时同步处理，优先改为稳定页面 ID 和每张图自身的 bounds，避免复制出只能处理原 11 页的程序。

修改已有交付物时直接编辑该文件，保留用户已经接受的内容与交互；只将本次范围所需的改动引入。说明文字的修改不应顺带改变布局和图形语义。

## 实现和交付

- 默认交付独立 HTML，内联 CSS、JS 和 SVG，离线打开即可使用；来源链接可以联网打开，核心内容和交互无需联网。用户偏好下载文件，不自动创建或更新托管网站。只有明确要求发布时才进入相应发布流程。
- 封面承载系列标识和主题；正文仅保留一套底部文字 step 导航。图例、示例声明和阅读提示放进图解右上角 info，避免常驻占据画布高度。
- 完整图使用可点击的 SVG 或等效矢量实现，不嵌入包含旧标题和脚注的整张截图。默认 fit，提供缩放、拖动和一键恢复 fit。避免页面与画布嵌套滚动；小屏允许页面滚动，图解本身使用固定高度的 fit 画布。
- 让交互服务于理解：例如选择查询 token 看可见范围，选择路由查看专家分配，选择 rank 看本地分片，选择 trace 事件定位模型节点。不要为了显得交互丰富加入无关控件。
- 校验概念、shape、箭头方向、图元语义和示例声明；检查选中解释、页码跳转、info、fit 与缩放后点击、窗口变化和离线依赖。视觉检查应覆盖长标题、单行网格、参数网格和完整图。工具只验证语法或模拟 DOM 时如实记录验证范围，不当作真实浏览器布局检查。
- 校验实际准备交付的那份文件，而非另一个工作副本。独立导出使用明确主题名和修订标识，并确认字节与最终源一致。更新已有 Library 文件时保留身份与版本保护，按 Library 流程保存；新主题创建新文件。不要复用已给过旧内容的模糊下载路径，也不要把托管链接当成离线交付。

最终简要说明成品的主题、关键交互与本次变更，提供已保存 HTML 的下载链接。
