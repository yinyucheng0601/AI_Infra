# 页面交付约定

## 分层约束

1. 控件层最严格。调用约束记录要直接复用的共享组件、token 与交互状态，包括工具栏、图标、按钮和面板。验收运行到最终入口，逐项核对几何、材质、选中和返回行为。
2. 内容层优先复用现有完整 Pattern。调用约束记录模块入口、renderer、视图结构和代表操作。用户指定参考时，把对应模块和联动列为必选项。
3. 数据和证据从当前案例推导。把配置、步骤、Tensor、缓冲和源码关系映射到 Pattern 的输入，核对对象身份和证据口径。

详细 UI 实现与验收见 Spatial Systems UI 的《可视化交付契约》。控件、模块和数据分别记录来源与检查结果。

## 页面内教程入口

新生成的计算可视化页面须提供按需打开的教程模块，入口放在 info / 帮助中，使用居中窗口，不占主体画布。按“价值 → 使用 → 扩展”组织，方法与实现说明仅在有助于使用时补充；调用 prompt 与带选择继续调查放入“使用”；方法放在最后。内容必须对应当前案例、实际使用的 Skill 和能力边界，不照搬 Case05 公式或结论。外部工具的增益须具体到新增的数据、可执行模型及验证资产，区分 agent 能自行推导的内容与必须由标定、测量或外部记录提供的输入；不以实现分工替代能力说明。prompt 代码块右上角提供有可访问名称的复制图标及复制失败反馈。复用参考 `prototypes/logsumexp-case5/page.html` 的 usageWindow，或 `prototypes/compute-investigation-trial/tutorial.html`；总 workflow 介绍以当前版本为准。验收入口、关闭、复制与正文可读性，打开教程不重置画布选择或视角。


## 跨页面一致性交付自检

- 迁移已命名的工作台时，从参考页面复用右上角控件的实际 SVG 或组件，并对齐尺寸、间距、材质和功能顺序（核查 → 当前选择 → 源码/原始数据 → Info）。将点击回调适配到新业务。浏览器中逐一打开并返回，核对图标与功能；需要省略时在交付记录写明缺失的数据或能力。
- Hover tip：所有 UI 控件含动态生成控件、菜单选项、输入、关闭、复制及画布可交互对象都有功能提示，并能由键盘聚焦触发。每个控件只用一套 tooltip；自定义提示不叠加原生 title，文字随配置和状态更新。
- 修改共享模板后检查 prototype 下所有实际交付页及已收录副本；区分模板、别名与最终入口，核对源模板重建后仍一致。记录覆盖页面、业务例外、检查方式和未验证项，不以静态扫描替代实际视觉验收。


- 参考 Pattern 的交互清单同时覆盖独立功能入口和内联图层。例如有缓冲生命周期、硬件映射时，分别验收按钮、面板打开、步骤联动、源码定位及关闭后视角。内联 Tensor 图仅覆盖内联关系。 有指定演示时，两页用同一视口和相同控件状态并排核对。记录入口呈现、展开位置、模块样式、拖动与缩放行为。数据适配优先从组件接口进入；展示形式的偏差须在交付前说明。
- Liquid Glass 在最终入口验收。检查宿主样式计算结果，确认控件有生效的滤镜、高光和透明背板，面板使用半透明磨砂。 Chromium 在有内容经过背板的位置核对折射；同时核对选中状态的项目色值和文字色。
