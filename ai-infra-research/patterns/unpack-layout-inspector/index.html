教程 · 如何调用 AI Infra 可视化仓库来实现本可视化工具？
1 · 价值
围绕拆分索引、输出布局与任务核分配建立可点选的证据链，减少索引换算与源码定位的往返。
源码与假设 → 映射视图 → 点选证据 → 继续核查
2 · 使用
把下面的 prompt 交给能够读取这两个仓库的 coding agent。用户不必记住 Pattern 名称，由 agent 查阅 AGENTS.md、Skills 与已有资产。
prompt
分析 heiheiha798/Ascend-Kernels-S8 / Unpack / 当前配置，不要修改算子。
先读取 AI_Infra 的 AGENTS.md，使用 ai-infra-investigation 总 workflow。
从 ai-infra-research/methods/ 读取当前 Skill，按任务调用领域映射、
计算图元、证据工作台和 Spatial Systems UI，固定算子 commit。
识别数学输入集合与当前生效实现的请求集合，分别推导索引、
源地址、分块、搬运后布局和计算输入，并关联源码位置。
复用 现有映射调查原型的布局与交互，以及正式图元，
生成独立 HTML。选择有代表性的普通块与边界块，不固定为 8／7 列。
无法确认的 API 行为和分析前提就近呈现，不将源码推导当作运行结果。
独立验证覆盖、遗漏、重复，以及复制上下文与当前选择的一致性。
遇到不支持的语义，明确指出缺口，不猜测映射。
带当前选择继续调查
右上角核查入口保留全部同步候选。点选候选可跳到已绑定的 shape 与 Task，并展开同步路径；点选步骤查看源码。没有可达预设的候选直接查看源码，不虚构配置关联。
在调查面板填写问题，点击“复制上下文”，将文本粘回原会话。内容包含对象、地址、参数、源码位置与分析前提。
prompt
请基于下面复制的对象与源码证据，核对我提出的映射或边界假设。
先验证分析前提与对应 API 约束，列出还需要的运行证据和最小验证方案。
不要仅凭图中标记认定 bug 或性能根因。

3 · 扩展
场景需要适配的语义
其他归约轴、stride、分块、有效范围与写回
转置 / 切片索引变换与源、目标布局
Gather / Scatter间接索引、重复访问与写入冲突规则
分块搬运请求槽、对齐、padding 与有效数据
先验证同一视图覆盖普通块、边界块和另一组 shape，再迁移到第二个实现。每类实现需要语义适配与独立验证，不能只换 shape 就声称支持。
解决什么问题，尚未证明什么
帮助减少多维索引与线性地址的脑内转换，核查尾块、padding、mask 的边界，并让人与 agent 围绕同一份精确证据讨论。
现在既可核对索引假设，也可从静态扫描候选发起同步调查；页面展示已保存的扫描结果，不能替代设备运行或 profiling。普遍收益尚待开发者任务对比验证：定位耗时、遗漏率与沟通往返次数。
CANNBot 接入：从核对映射到发现同步候选


接入 ascendc-sync-audit ↗，使用其结构扫描与数据流分析脚本。扫描固定版本的 Unpack 源码，结果随页面保存；浏览器内不会重新运行扫描器。


接入前现在增加的核查能力


开发者提出索引、地址或任务假设，再点选核对。结构扫描主动提出同步候选，包括提前退出可能跳过 Set，以及计算后搬出前可能缺少同步。


图中关联元素、Task、Core 与源码。增加搬入 → 同步 → 计算 → 同步 → 搬出的源码调用链，关联 buffer、执行流水与源码行，便于逐步核对候选。


复制当前对象，手动补充调查线索。候选绑定可达 shape 与 Task；点选后跳转，复制上下文同时携带扫描证据与当前选择。




本例实际结果：结构扫描给出 3 项候选，数据流分析没有新增候选。图中路径与 shape 的绑定由本项目适配器完成，扫描器本身不理解这些配置，也没有证明实际设备访问正确。


已用上游好例、坏例及本地修订样例验证扫描链路，并重新扫描比较结果。真实 Unpack 未修改，候选仍需核对控制流、同步 helper 与 API 语义；数据流分析采用正则前端，未报出问题不等于安全。下一步可带着选中证据提出最小修改，再重扫并补充设备验证。


候选复核：初始显示“待复核”。在“继续调查”点击“模拟复核”，展示已保存的 3 项源码复核结论与绿色“已排除”标签；此按钮不调用 agent、不重跑扫描器。随后点选候选可查看逐段源码依据与仍需的设备证据；原始扫描消息完整保留。复核对象携带源码版本与哈希，并随“复制上下文”导出。新候选默认“待复核”；依据不足时应记录“仍需验证”，不能为了清空列表而排除。


4 · 实现分工
本案例从固定版本的 Host / Kernel 源码建立索引与任务模型，再关联地址、任务分配、源码和调查上下文。总 workflow ai-infra-investigation 按任务组织以下能力。
步骤 / Skill在本案例中的作用
领域映射
operator-mapping-investigation		建立逻辑索引与实现映射，核对地址、任务区间和搬运范围，保留分析前提。
计算可视化图元体系
ai-infra-glyphs		从正式图例库复用 Tensor、OP 与数据角色，保留标签结构和类别图标。
证据工作台
observability-design-style		组织对象选择、差异、源码依据与可复制的调查上下文。
空间界面
design-spatial-systems-ui		实现无限画布、关联路径、浮动面板与缩放，切换对象时保持视角。
最后分别检查映射覆盖、图元与交互，构建独立 HTML。总 workflow 还可按任务路由到 llm-compute-diagrams，处理模型机制、编译变换、并行通信或运行证据；新场景仍需对应的来源与语义适配。查看总 workflow 与使用说明 ↗
