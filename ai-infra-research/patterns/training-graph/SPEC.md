## 1. 产品目标

在同一张可缩放、可拖拽的计算图上，逐步回答：一个 Transformer Block 如何从模块定义展开为前向与反向依赖，又如何因 TP、SP、缓存策略、MoE 和 EP 改变张量形状、数据归属与通信。

用户既可以顺序播放，也可以拖动主轨定位步骤，再调节该步骤的参数，观察变化。右下角 Rank 视图回答“这些对象放在哪里”，与计算图的“这些对象如何计算”互补。

核心用户：需要理解并行训练机制的模型开发者、基础设施开发者和技术设计者。典型任务包括解释输入梯度与参数梯度的区别、比较 TP/SP 的通信变化、追踪一个 token 的 Top-2 专家路径，以及核对专家的 Rank 归属。

成功标准：用户能将变化定位到具体算子、张量、专家和通信组，而不需要在互不对应的图之间猜测关系。

## 2. 范围与基本口径

| 项目 | 当前约定 |
|---|---|
| 模型基线 | `model.py` 定义的 12 层 Pre-Norm Transformer；主图展开一个 Block |
| Block | Norm → Attention → Residual Add → Norm → FFN → Residual Add |
| 固定尺寸 | T=8、H=8、FFN 隐藏宽 F=16、4 个注意力头；省略 batch 维 |
| Attention | 因果注意力；QKV、MHA、输出投影 PROJ；本例不展开 Dropout |
| Dense FFN | FC1 → GeLU → FC2 |
| 公式约定 | 行向量写法 Y=XW；W 为输入特征×输出特征，与 PyTorch Linear 的存储方向相反 |
| 部署资源 | 固定 8 个 Rank；前四步尚未指定对象的部署归属 |
| 并行范围 | TP、SP、EP；DP/专家副本关系随资源约束推导；PP=CP=1 |
| 数值来源 | shape、分片、路由由本例规则推导；未接入训练 Trace 或实测显存 |

主进度表达“依赖与部署规则逐步加入”，不表达训练执行时间。DGRAD 与 WGRAD 属于同一次反向传播的两类梯度计算，不是两轮训练。

## 3. 页面结构

- **全窗口主体画布**：默认显示计算图，滚轮缩放、拖拽平移；步骤和结构参数变化后自动 fit。
- **左上标题**：主标题“分布式训练”，副标题“模型 → 计算 → 通信”。
- **左侧步骤说明**：大号步骤编号、当前变化、关键公式、配置摘要。切换 Rank 主视图后改为所选 Rank 的解释。
- **右上配置**：逻辑阶段显示未部署状态；部署阶段显示固定 Rank 总量与当前 TP/DP/EP。
- **Info 入口**：收起图例、公式口径、范围说明和官方依据，避免常驻说明占据画布。
- **底部主轨**：播放/暂停、九个步骤名称、可拖动进度条。参数区域展开不推动主轨位置。
- **二级参数区域**：位于主轨上方，仅显示当前步骤适用的参数；专家分布步骤另含专家数控制。
- **右下辅助视图**：默认是典型 Rank；点击与计算图交换主体。Rank 主视图时，这里显示完整计算图缩略图。
- **悬浮检查器**：点击节点或 Rank 对象显示对应详情，不使用底部固定详情条。
- **缩放工具**：缩小、适应、放大；始终控制当前主体视图。

## 4. 九步推导

以下编号为界面展示编号 01–09，源码 `stage` 为 0–8。

| 步骤 | 新增的信息与图形变化 | 可调项 | Rank 语义 |
|---|---|---|---|
| 01 模型架构 | 展示两个 Pre-Norm 子层、输入输出和残差；Attention/FFN 保持模块级 | 无 | 未部署；仅保留暗色无标签的 Rank 占位外框 |
| 02 前向 | Attention 展开 QKV → MHA → PROJ；FFN 展开 FC1 → GeLU → FC2；加入参数与中间张量 | 无 | 仍不指定 Rank 归属 |
| 03 DGRAD | 从输出梯度沿依赖反向计算输入梯度；补充 Norm、激活函数和残差的反向路径 | 无 | 同上 |
| 04 WGRAD | 加入线性层参数梯度分支，明确读取前向输入与输出梯度 | 无 | 同上 |
| 05 TP | 在线性层切分权重和中间特征；局部结果加入归约；映射固定 8 个 Rank | TP=1/2/4 | 全部 Rank 0–7 出现，显示 TP 分片与 DP 副本关系 |
| 06 SP | 在 TP 组内按 token 行切分子层边界；前向 AG 收集输入、RS 归约并分片输出 | SP 开/关 | 本地 token 行与 TP 组对应；Rank 总数不变 |
| 07 反向取数 | 比较保留完整 X/A 与只保留序列分片；后者在 WGRAD 前增加两处输入 AG | 完整/分片缓存 | 显示当前 Rank 保存与取回的输入 |
| 08 FFN→MoE | 将 Dense FFN 替换为 Router → 专家重排 → 独立专家 → 加权合并；保留 Norm、残差和子层接口 | 专家数、token | 专家池尚未分配到 Rank；已有 Attention/Router 等归属仍可查看 |
| 09 专家分布 | 保持专家计算，增加专家归属和 EP 分组；跨组路径使用 Dispatch/Return All-to-All | EP、专家数、token | 显示全部 Rank 的专家分片、副本及所选 token 的路径 |

### 4.1 关键公式与 shape

```text
Block:
Ha = H0 + Attention(Norm1(H0))
H1 = Ha + FFN(Norm2(Ha))

Linear:
Y = XW
dX = dY Wᵀ          # DGRAD：向前层传递的输入梯度
dW = Xᵀ dY          # WGRAD：参数更新所需的梯度
```

对 TP 度数 p，权重 shape 为：

| 参数 | 本 Rank shape | 切分方向 |
|---|---|---|
| Wqkv | [8, 24/p] | 输出特征 |
| Wproj | [8/p, 8] | 输入特征 |
| W1 / 专家 W1 | [8, 16/p] | 输出特征 |
| W2 / 专家 W2 | [16/p, 8] | 输入特征 |

SP 开启时，边界张量为 `[8/p,8]`，AG 恢复为 `[8,8]`；RS 对各 Rank 的 `[8,8]` 部分结果求和，再按 token 行输出 `[8/p,8]`。关闭 SP 时边界保留 `[8,8]`，TP 的行并行结果使用 AllReduce。TP=1 时不产生 TP 通信。

缓存策略仅在有效 SP 开启时形成对比；重新 AG 是本例选择的输入保存策略，不是所有训练系统的必选流程。

## 5. 参数与约束

| 参数 | 取值 | 默认存储值 | 生效范围 |
|---|---|---|---|
| TP | 1 / 2 / 4 | 4 | 步骤 05 起；此前逻辑图按 TP=1 展示 |
| SP | 关闭 / 开启 | 开启 | 步骤 06 起且 TP>1；TP+EP 时按本例约束启用 |
| 缓存 | 完整 / 序列分片 | 序列分片 | 步骤 07 起；无有效 SP 时控件禁用 |
| 专家数 E | 4 / 8 / 16 / 32 / 64 | 4 | 步骤 08 起，固定 Top-2；界面不再提供 Dense 开关 |
| EP | 1 / 2 / 4，并满足 EP≤DP | 2 | 步骤 09；此前专家尚未分配或 EP 不生效 |
| 跟踪 token | t0–t7 | t0 | 步骤 08–09 |

调整二级参数不改变主步骤；参数在后续步骤继续沿用。修改参数或 token 会暂停播放。调整专家数关闭旧的专家详情，避免保留已失效的节点内容。

### 5.1 固定资源与分组

```text
worldSize = 8
DP = 8 / TP
专家副本数 EDP = DP / EP
TP × EP × EDP = 8
Rank ID = (replica × EP + expertGroup) × TP + tpLane
```

EP 在 DP 维度内划分，不增加 Rank。增加专家数也不增加 Rank。

| TP | 推导 DP | 可选 EP | EP 最大时的 EDP |
|---|---|---|---|
| 1 | 8 | 1 / 2 / 4 | 2 |
| 2 | 4 | 1 / 2 / 4 | 1 |
| 4 | 2 | 1 / 2 | 1 |

改变 TP 时，若原 EP 超出可用范围，自动收敛到当前 DP。控件同步收敛，不展示不可达到的有效状态。EP 分组按连续专家编号等分，各组持有 E/EP 个专家；同组内部按 TP 切分每位专家的权重。

默认最后一步 TP=4、EP=2：Rank {0,1,2,3} 持有前半专家的四份 TP 分片，Rank {4,5,6,7} 持有后半专家；全部资源仍为 8 个 Rank。稠密参数梯度按 DP 组同步，同一专家分片按 EDP 组同步；这些关系在详情中说明，计算图暂不展开同步算子。

## 6. MoE 与专家规模

### 6.1 路由与统计

- Router 权重 `Wr[8,E]`，为每个 token 评分，取分数最高的两位专家，并只对这两项做 softmax。
- 专家计算 `Ei(a)=GELU(a W1i) W2i`；输出 `r_t=Σ α_t,i Ei(a_t)`，随后才进行外部 TP 归约及子层残差相加。
- 每位专家固定 `8×16+16×8=256` 个矩阵参数；本层 MoE 总矩阵参数为 `264E`，含 Router 的 `8E`。
- 单 token 使用的矩阵参数计数为 `512+8E`；该值不等同于 FLOPs、显存或执行延迟。
- 统计限定 8 个来源 token 的样本，Top-2 总计 16 次 token–专家分配。样本激活专家数是这 8 个 token 的入选集合大小，每 token 始终只选 2 位。
- 前四列 Router 权重沿用 Dense→MoE 参考报告；其余列使用固定正弦规则，数值可复算。路由样本独立于符号 Attention 计算图，无容量截断。

增加 E 同时改变 Router 宽度、参数总量、分数排名、入选专家、路由系数、负载分布和专家归属；不能仅复制更多卡片。TP、Rank 总数和 Top-2 不随 E 自动增加。

### 6.2 图形表达

- E=4/8：专家展开为 FC1 → GeLU → FC2；每行最多 4 位。
- E>8：采用用户提供的专属专家图标，叠加 E00–E63 编号，每行最多 8 位；点击在检查器展开内部计算。
- 在同一表达档内增加专家数量，节点尺寸不缩小；允许阵列扩展，用画布导航查看。跨 8→16 的表达切换有意从展开计算变为图标。
- 紧凑图标保持原始 71:91 比例，高度等于一个普通 OP 节点，文字与同图 OP 的最终字号一致。
- 当前 token 入选的两位专家保持原灰色填充；未入选专家 opacity=0.35，不改为白色选中。
- 专家分组上下堆叠且左右对齐。残差线走专家区域外侧，避免穿过算子。跨组路由为虚线，本组为实线。
- 步骤 08/09 自动聚焦并居中放大 FFN 区域；完整图保留在同一对象体系中。

## 7. Rank 视图与跨视图联动

### 7.1 未部署状态

步骤 01–04 的右下角保留 Rank 轴测外框，内部显示三条暗灰占位带，不显示 Rank 编号、TP 坐标或对象标签。此时入口禁用，不提前把逻辑计算对象放入某个 Rank。

### 7.2 部署状态

步骤 05 起，Rank 主视图始终保留 0–7，采用固定四列两行位置。参数变化修改分片、组关系、内容和连线，不重新增删资源。

色带表达当前 Block 的对象类别：权重、激活/缓存、梯度、通信。色带使用固定布局高度，顶部留有开放空间；不归一化填满外框。未配置设备容量和 dtype 字节预算，因此其高度、剩余区域都不能解读为显存占用率或空闲容量。

步骤 08 的专家仍在待分配池；步骤 09 才将具体专家写入各 Rank 的对象清单。一个专家可在多个 Rank 上拥有 TP 分片和 EDP 副本。

### 7.3 联动规则

| 操作 | 结果 |
|---|---|
| 点击右下角典型 Rank | Rank 成为主体，计算图进入右下缩略图；保留步骤与参数 |
| 点击计算图缩略图或返回 | 恢复计算图主体；同一步同配置时恢复先前计算图镜头 |
| 选择 Rank / 色带 | 更新所选 Rank 与类别详情，并在计算图缩略图中突出关联对象、dim 其他对象 |
| 点击计算图对象 | 更新对应节点详情，并联动适用的 Rank 对象/类别 |
| 点击已部署专家 | 联动该专家的承载 Rank；详情保留其所有副本的归属信息 |
| 选择 token | 两视图更新同一条 Top-2 路径，不修改专家本身的部署 |
| Rank 主视图下退回逻辑步骤 | 自动返回计算图，恢复未部署占位状态 |

专家计算图展开专家副本 0、来源组 0 的路径；Rank 视图覆盖全部副本，不把这条样本路径统计扩充为全局负载。跨组 Dispatch 与 Return 按相同 TP lane 连接。

Rank 主视图使用专属左侧说明，显示本 Rank 的权重分片、token 行、缓存或专家归属。移除重复的卡片标题、底部 Rank 胶囊和常驻容量横幅。

## 8. 交互、镜头与动效

### 8.1 主进度和播放

- 主轨复用 Layer Stack 的分段轨道表达，当前范围 0–64，九个语义锚点为 0/8/…/64。
- 拖动可经过中间刻度；当前步骤为 `round(cursor/8)`，中间刻度不是独立的执行帧或新的计算状态。
- 当前播放行为：点击后先进入下一步，此后每 3.2 秒前进一阶段；到最后一步暂停。在末步点击从头重新播放。
- 手动切换主步骤、修改参数、选择 token 或页面进入后台时暂停。Space 在非交互元素上触发播放/暂停。
- 左右方向键切换步骤，Home/End 到首尾；参数滑轨内保持原生键盘调整。

### 8.2 布局和镜头

- 布局按当前可见语义行计算节点高度与紧凑间距；不为尚未展开的节点预留大段空白。
- 步骤/结构参数变化触发自动 fit；普通阶段按当前图边界居中，MoE 阶段按 FFN 焦点边界 fit。
- 用户滚轮缩放以指针位置为中心；拖拽平移。计算图与 Rank 分别保存镜头，缩放工具作用于当前主体。
- 计算图辅助视图尺寸为 390×315，使用完整图边界的独立 viewBox 居中 fit；不继承主体的偏移或局部裁剪。
- 窗口 resize 重算适配范围。fit 与阅读性同时验收，不能以把节点缩成不可读小点作为合格布局。

### 8.3 连续性与状态

- 相同对象跨步骤沿用稳定 ID；已有节点按位置变化移动，新分支从对应模块/前向对象附近出现。
- DGRAD/WGRAD 通过前向对应对象建立动画锚点；MoE 从 FFN 位置展开；EP 在同一专家集合上引入分组。
- 新连线有路径揭示，退出节点淡出。布局动效由 CSS token 提供（缺省约 500ms），主辅画布交换约 400ms。
- 遵循 `prefers-reduced-motion`，减少动画时直接呈现目标状态。
- 详情必须与当前点击对象一致；所选对象在新配置中失效时不保留旧详情。

## 9. 视觉与可访问性契约

| 对象 | 表达 |
|---|---|
| 张量 | 正式矩阵图元，带名称与 shape；激活绿色、参数紫色、梯度青色 |
| 算子 | 正式 OP 胶囊与类别图标；通信操作使用虚线轮廓 |
| Attention/FFN 区域 | 白色 5% fill，无 border |
| Rank | 复用本地 Rank Pattern 的轴测几何与规划模型；对象类别色带 |
| 专家 | ≤8 展开计算，>8 使用专属 SVG 图标；同图字号一致 |
| 控件选中态 | 胶囊实心高亮与深色文字；不以描边或外框表达选中 |
| Top-2 路径 | 采用第 6 节的灰色原态与其余 dim 规则，独立于控件选中态 |

控件提供单一 tooltip、键盘焦点与必要的 aria 状态；避免原生 title 和自定义提示叠加。文本对比度需在实际灰色填充与 dim 状态下检查；dim 仅降低非当前对象优先级，不能使必要标签无法辨认。

## 10. 实现架构与数据契约

```text
步骤 + 参数
   ↓
graph-model.js          模型配置、约束、语义行
   ↓
graph-layout.js         可见行与专家阵列布局
   ↓
training-graph.js        图节点、边、说明与元数据组装
   ↓
graph-renderer.js       按稳定键增量更新 SVG、按帧合并渲染

同一配置 → rank-model.js → 本地 planner → rank-view.js
                    两视图通过对象 ID / Rank / 色带类别关联
```

| 文件 | 职责 |
|---|---|
| `model.py` | 本例模型定义基线，不是当前网页的自动导入器 |
| `graph-model.js` | 固定模型与部署配置、派生规则、可见行、`training-graph.v1` 快照 |
| `graph-layout.js` | OP/张量行布局、专家阵列尺寸与分组位置 |
| `training-graph.js` | 前向/反向/MoE 依赖、端口、节点注册信息、路由统计 |
| `graph-renderer.js` | SVG 键控更新、帧调度与更新统计 |
| `rank-model.js` | 共享配置到 Rank 对象、通信组、权重与专家归属的适配 |
| `rank-pattern/` | 本地正式 Pattern 的规划函数与轴测几何；来源指纹独立保存 |
| `rank-view.js` | Rank 渲染、主辅交换、镜头、选择和对应说明 |
| `demo.js` / `secondary.js` | 步骤、播放、交互状态、参数控件和左侧叙述 |
| `canonical.js` / `expert-glyph.js` | 正式图元与用户专家图标接入 |
| `content.js` / `sources-audit.md` | 文案依据、公式与来源口径 |
| `build-offline.py` | 将入口及依赖打包为离线单文件 |

快照节点包含 `id / label / description / kind / shape / role / objectId / sources / layout`；边包含 `id / from / to / role / relation / sourcePort / targetPort`。展示 ID 与共享参数 objectId 分离，以区分同一参数的多处引用。

Rank 对象包含 `id / lane / group / replica / objects / experts / tokenRows / bands / tpGroup / epPeers / dpPeers / expertDP`。专家结构步骤不得提前写入专家的部署 ownership。

参数改变时推导当前状态，不预生成全部组合。SVG 更新保留稳定节点；连续输入通过帧调度合并。当前仍有图字符串组装、元数据和说明耦合，不能据此宣称已具备通用编译器或任意模型可视化能力。

## 12. 暂未实现与扩展边界

- PP 的多层模型/流水调度、CP 和独立 DP 调节；后续如加入 PP，应先建立 layer stack 与 stage 部署模型，再表达跨 stage 的激活和梯度通信。
- 任意模型工程导入、Python/FX 图抽取、自动识别分布式框架配置。当前 `model.py` 是参考基线，图规则由前端显式实现。
- 真实容量、dtype、内存生命周期、优化器状态和精确峰值显存；当前 Rank 图不能用作设备容量规划。
- MoE 内部完整反向细节、偏置梯度、Norm 参数梯度，以及展开的 DP/EDP 梯度同步算子。
- Trace 时间轴、实测通信量、网络拓扑和性能瓶颈诊断；动画时长不代表运行耗时。

后续产品化应将模型结构、并行部署和运行观测分开输入，再由共享语义图驱动布局与视图；导入代码工程不能直接等同于获得完整部署与实测性能信息。
