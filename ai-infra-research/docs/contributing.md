# 收录流程

1. 判断设计价值与范围，不以目录名或扩展名自动定类。
2. 确认来源主版本，检查副本、敏感信息、归属和依赖。
3. 用模板整理成果，说明问题、设计贡献和可复用部分。
4. 在 catalog/assets.json 登记元数据。来源仓库尚未确认时 URL 留空，不使用本机绝对路径充当团队入口。
5. 按实际证据标记成熟度；列明未验证部分和 mock 数据。
6. 运行校验，内容评审通过后再纳入展示。

成熟度：draft（整理中）、reviewed（内容已审）、validated（附对应验证证据）、archived（历史参考）。validated 不自动表示经过视觉、功能及用户验收的全部检查，必须阅读 validation 字段。

第二阶段展示应支持领域/内容分类，突出设计问题、贡献、成果和复用入口。不要堆砌无意义标签；没有可访问内容的资产不伪装成可打开的卡片。
