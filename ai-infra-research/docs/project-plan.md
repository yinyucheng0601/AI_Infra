# AI Infra 设计研究与资产库 · 项目计划

更新：2026-09-16。项目名：ai-infra-research。用户已确认设计 scope，并授权本轮自主处理一般设计和实现决策；该授权不等于公开发布、敏感资料开放或扩大项目范围。

## 1. 目标与使用者

服务三个场景：个人/团队设计成果盘点、内部汇报、团队资产积累。让散落各仓库的设计成果能被发现、读懂、追溯和复用，而不是再建立技术项目大全。

汇报者需要看清研究课题、设计判断与成果；团队成员需要找到可用的内容、模式和方法；维护者需要知道来源、版本、验证状态及更新责任。

## 2. 范围

收录知识与洞察、产品与体验规划、Web/TUI/3D 界面和交互、信息可视化、设计系统、视觉模式及设计方法。技术白皮书须说明设计价值；从开发项目中提取设计成果，不搬迁后端实现。

不收纯后端、算法代码、基础设施、第三方样例、无设计贡献的项目、重复副本、临时输出和未经筛选的原始访谈。model_skill-dss3.2new 不进入白皮书类别。

主类型与业务标签分离；PTO/Pangu/CANN/Ascend/DevKit 不是互斥内容目录。设计说明、实现和验收结果分别记录。第一轮 2,302 个文件仅是候选，不能作为成果计数。

## 3. 三阶段交付

| 阶段 | 工作包 | 交付物 | 完成标准 |
|---|---|---|---|
| 1 仓库框架 | 定位、范围、协作规范、元数据、模板、目录校验 | README、scope、contributing、catalog、模板与校验脚本 | 本地 Git 就绪；规范可执行；不误导为已收录大量成果 |
| 2A 内容策展 | 保留原 gallery 有价值知识、跨仓补充、去重、设计价值标注 | 精选资产目录、内容说明、来源与指纹、排除说明 | 每篇有真实来源、设计用途、分类和内容概要；无纯开发项目和敏感原始材料 |
| 2B 展示演进 | 延续 whitepaper-gallery 的结构、设计系统和卡片；跨项目分类、搜索、详情、来源阅读 | 独立仓首页、详情页、PTO 兼容入口、launch-v2 更新 | 可按主题/形式/领域检索；计数一致；来源可打开；错误可见；键盘可用 |
| 2C 维护与交接 | 来源映射、可重复构建、依赖和链接检查、部署说明 | 本地预览服务、测试、验证记录、运行文档 | 不依赖首页中的用户绝对路径；服务只绑定回环地址；未映射来源有明确提示 |
| 3 方法与 Skills | 从实践提取方法、选样、定义输入输出、测试及版本管理 | 少量有示例和验证标准的设计 Skills | 至少一个知识→表达模式→生成/检查流程闭环；不批量复制现有 Skills |

阶段 1 已完成；阶段 2 首批实现已交付：16 篇目录、筛选与详情、独立首页及 PTO 兼容入口、受限本地阅读服务。自动检查已完成，视觉验收明确留给用户，3 篇源文章的历史依赖问题已记录并在页面提示；阶段 3 不在本轮实施。详见 validation.md。

## 4. 第二阶段信息架构

首页按阅读课题组织：计算生态、算子与硬件、训练与并行、产品体验、计算问题表达。内容形式筛选区分白皮书、知识地图、产品分析、设计报告、设计说明。领域筛选支持跨项目查找。

每张卡片提供简明标题、摘要、来源项目、形式和阅读入口；详情包含设计用途、内容提纲、来源路径、源文件校验指纹及相关条目。不要以“已验收”装饰未经验证的内容。不要把文件路径当成主要展示文案。

本轮没有新建白皮书或改写其技术结论，只做索引与策展。来源内容反映原材料时点，不承诺所有技术信息实时正确。

## 5. 技术与来源策略

- ai-infra-research 维护唯一的人工目录和页面源文件；PTO 根目录保留 whitepaper-gallery.html 兼容入口，从 launch-v2 进入。
- 延用旧 gallery 的卡片布局与 PTO 共享 tokens、button、tab-control、card-demo、panel-shell；不创建新的视觉语言或复制整套设计系统。
- 原文章继续保留在各源仓库。独立预览服务根据被 Git 忽略的本机映射解析来源，只暴露入选内容及必要静态依赖，不暴露整个家目录或仓库。
- 目录只记录仓库键、相对路径和可验证指纹；本机路径放在 .local 配置。团队使用时更换映射即可。
- 先支持本机内部预览。远端仓库权限、发布基础路径、外部依赖和敏感审查另设发布门槛，不自动发布。

## 6. 验证与验收

自动检查：元数据完整性、ID 唯一性、关联存在性、收录排除规则、来源存在和指纹、入口和一阶静态依赖、过滤/URL 状态逻辑、HTML/JS 语法与 HTTP 端点、目录越界/敏感文件拒绝。

人工验收：桌面及窄屏、明暗主题、阅读层级、键盘导航、长标题、空结果、来源阅读。遵循本机工作流，不默认做浏览器自动化或截图；自动检查通过不等于视觉验收完成。

来源文章可能自身有历史失效链接、CDN 依赖或运行时动态资源。本轮不顺手重写文章，发现后记入验证报告。

## 7. 风险与应对

| 风险 | 处理 |
|---|---|
| 同名/副本/不同版本 | 记录精确相对路径和内容 SHA256，不凭目录名判最新 |
| 跨仓本机可用、团队不可用 | 本机配置分离，提供示例配置和未连接提示 |
| 原始研究包含个人信息 | 首批排除，不默认转存或暴露 |
| 目录计数被当成成果或验收数 | 明确“收录内容”，不展示未经证实的成熟度比例 |
| 源仓持续变化 | 校验指纹并报告漂移，重新审阅后再更新 |
| PTO 工作区已有大量改动 | 只改 gallery、对应启动入口与一条变更记录，保留其他变更 |

## 8. 决策记录

- 保留 ai-infra-research 名称，定位为设计研究与资产库。
- 第一阶段索引优先，不搬迁源仓；没有来源发布权限的条目不自动公开。
- 从已有 whitepaper-gallery 演进，保留 PTO 根目录兼容路径。
- HNSW、VLSI 等只以“计算问题的信息表达”收录知识页，不纳入算法实现项目。
- TUI 视觉说明可作为知识内容先收录；pattern 抽取与 Skill 封装留待后续。
- 用户离线期间代理可自主审阅实现，不虚构用户已完成视觉验收。

第二阶段交付后先收集用户视觉与内容反馈，再补充设计案例和 pattern 关联。第三阶段优先选择：知识材料到视觉文章、技术对象到架构图、任务流程到 Web/TUI 交互三类已有实践；每类先完成一个可复现实例，再扩充数量。
