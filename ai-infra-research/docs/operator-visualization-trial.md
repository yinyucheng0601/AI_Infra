# 算子调查可视化：首次试用

这次试用的是源码与视图之间的调查流程：选择一个输出或输入，核对逻辑元素、地址、搬运后位置与参与计算范围，再带着问题回到源码。适合已经遇到索引、布局或边界疑问的任务；普通报错或单项耗时查询可以先用文字处理。

## 先看结果

从 Library / Pattern 打开「归约访存检查 · LogSumExp」。选择 y 矩阵中的一个输出，再选择绿色输入，查看 GM、UB、work 的关联；打开源码映射核对表达式，在调查面板复制问题与证据。

这是固定 Case05 页面，不会自动分析任意源码。当前可复用的是图元、交互和建模方法；同类新配置或不同 API 需要适配与验证。

## 一个入口，四个职责阶段

在 Skill 页选择「AI Infra 计算可视化 · 总 workflow」，无需自己决定 Pattern。它调度领域建模、正式图元、证据组织与界面呈现。完整分工见 [Skills 维护入口](../methods/README.md)。

需要安装时选择详情中的“下载完整 workflow（6 Skills）”：解压后六个同级目录分别是独立 Skill。仅下载总 workflow 的单 Skill ZIP 不包含依赖。按所用 agent 的当前安装机制配置；也可按前述 checkout 路径直接读取，无需安装。

组合包带正式图例库的指纹快照，但不带 Case05 原型，复用该原型仍需 checkout。下载 HTML 只能试交互，不等于安装 Skill；组合包也不代表已经支持任意 API。

## 怎样反馈、怎样拓展

反馈任务、使用的 Skill 版本、生成结果和卡住的位置即可；不需要正式评测。最有价值的是：确认了哪个原本难以理解的关系、哪里画错了、哪一步比文字更费事。公开反馈前移除私有源码、路径与数据。

同一适配器先覆盖普通块、边界块与另一组合法配置；再次检查独立参考。再迁移到第二个实现，核对其 API 与布局，不能只换 shape 文案。转置需建模索引置换；Gather / Scatter 需建模间接索引及重复或冲突语义。没有适配证据就保持部分支持，不称为自动诊断。

当前没有通用调用协议或实时会话回传。普遍收益仍需比较定位耗时、遗漏率和沟通往返，源码模型与 CPU 检查不代表 NPU 已正确运行。
