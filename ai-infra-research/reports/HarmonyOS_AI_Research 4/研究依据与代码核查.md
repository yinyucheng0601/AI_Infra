# 鸿蒙应用 × 模型：依据与代码核查说明

研究日期：2026-11-25。主报告为 index.html。所有方案及构造场景均未接入真机。

## 任务判断

领导原话同时涉及 Swift/Core AI、ArkTS/ArkUI、应用能力对象和 Agent 使用方式。本报告据此提出研究假设：新特性应连接模型交付与应用能力验证，服务层与 IDE 窗口解耦。该解读不是对领导意图的确定事实；它通过后续可验证的 PoC 变得具体。

## 1. 两份调试信息，分别服务于来源回溯与现场捕获

模型导出时的操作级元数据决定是否能显示 PyTorch 模块和源代码。缺失时仍能显示操作、结构和 Inspector。应用运行现场的 Include Model Debug Information 是 Xcode Run scheme 的另一个开关，要重建重跑；Gauge 还需要在目标事件发生前打开。官方说明该开关影响设备专门化开销，不影响 Load 与 Inference 计时，因此测首次准备性能要关闭它。

Gauge 文档将自身定义为实时 Debugger 会话与特定 Inference 输入捕获的唯一入口。输入可以导出为单张量 .npy 或多张量 .npz。这说明独立应用和应用现场采集是不同工作流。报告没有据此推断 Apple 未公开的底层服务是否存在，也没有将 Python 离线接口等同于 Xcode 现场接口。

## 2. SAM3 的局部精度策略有完整的决策链

WWDC 325 展示原始 float32 资产超过 3 GB，统一激进 int4 后约 430 MB；10:24 画面可读为 428 MB。遮挡花朵漏检。Debugger 通过参考中间值、同步点及模块映射，把低 PSNR 聚集到 detector decoder；编码器约占 96% 参数，检测器约 4%。跳过检测器权重量化后重跑，演示画面显示 467 MB，并恢复检测。

这证明了该示例的局部干预价值，不证明完整数据集质量、速度提升或其他模型的敏感模块。相似度聚集不是自动因果证明；局部改动和任务结果复验补充证据。报告未转录示例的 PSNR 值为建议阈值。

当前仓库 SAM3 iOS lite 配方是另一项证据：图像编码器 w4 k-means palettization、group_size=32；文本编码器 w6、group_size=8；检测器 fp16，不做权重压缩。输入默认 336，静态文本长度 32，BC1S 布局与 Conv2d 1×1 投影。不能把它说成 WWDC 中 Mac 统一 int4 模型的同一产物。full 选项导出原始 HF Sam3Model，单 main，默认 1008、float32。

## 3. 词卡应用串起模型、任务适配器与结构化状态

WWDC 326 的应用从图像和文本提示得到 SAM3 掩码，再让 Qwen 生成中文词、英文释义、例句。Swift 的 ImageSegmenter 包含 tokenizer、输入预处理和输出后处理；CoreAILanguageModel 让自有模型使用 Foundation Models 的会话接口。VocabCard 的 schema 保障结构约束，不能保障图片与词义匹配、内容正确或当前页面归属正确。

首次转圈发生在 SAM3 首次实例化与分割前，未进入语言模型生成。Instruments 中 Load 包含较长 Specialization。官方由此讨论 opt-in 模型下载、Background Assets、首次使用引导与 coreai-build 提前编译。提前编译资产按架构选择，最终专门化仍与设备和 OS 有关。开发主机 Mac 的工作和运行 Mac 应用的角色必须区分。

手机演示使用 Qwen 0.6B；Mac 演示转为素材批量整理并使用 Qwen3 8B。源码中 iOS LLM 入口拆为 load_embeddings、gather_embeddings、extend、prompt_opt；macOS 为 main 与模型可选 prefill。这些是核查到的配方，不能推导为所有 iOS 模型都运行在 Neural Engine、所有 Mac 模型都运行在 GPU。

## 4. Agent 接口不是只有 Skills 和 CLI

coreai-torch 的 Python 调试文档包含 compare_program_intermediates、compare_compute_plans、compute_changes、attributions_by_op_id 与 benchmark_coreai_program 等接口。结构变化报告提供 to_dict；模块路径区分 Linear$3 / Linear$4 等实例，包含文件、行、列。数值与设备放置报告也可按模块聚合。这是独立于 GUI 的程序诊断证据，但不覆盖应用内现场捕获的全部需求。

源码来源依赖转换时调试栈。缺失时差异仍存在，来源为 unknown。比较能力受映射和可采集中间值限制，不能声称所有变换后的节点都有精确一对一映射。公开高层文档与当前 Python 文档对 save_intermediates 的参数呈现不完全一致，主报告因此只表达文件契约，没有给未经运行验证的完整可执行调用。

## 5. 自动实验必须保留测量对象

压缩脚本的 size_mb 是理论权重大小。experiment_runner 的 duration_ms 包含 prepare 和 forward，不是目标手机纯推理时间。仓库输出格式说明里的示例数字不是运行数据，本报告没有把它们画成基准图。

Swift benchmark 可输出模型、prompt/generation token 数、试验次数、batch、准备时间、cache_hit、预热时间、逐次吞吐与可选 peak_memory。它禁用 prefix cache，避免同 prompt 的 prefill 计成缓存恢复。随机 token prompt 和 temperature=0 服务于吞吐测量，不是任务质量评测。并发总吞吐不能直接当成单请求时延；内存字段未启用或采集范围受限时不能按零填充。

CoreAILanguageModel 在 schema 请求时检查引擎的 supportsGuidedGeneration，不支持时抛出 unsupportedCapability。工具定义还要经 tokenizer/template 编码，工具调用流与普通文字分发不同。统一 API 不等于所有 provider / engine 可无条件互换。

## 6. 鸿蒙已有工具是需要复用的基础

官方 ArkUI State 文档已提供状态变量修改、归属类与组件、当前值，以及关联组件刷新与布局耗时。Inspector 已支持组件树、源码跳转、状态及离线快照。HiTraceChain 已提供链与 span，async/await 与 Promise 等可自动传递；TaskPool、Worker、宏任务及部分 Native 通路需要手动桥接。本报告不把一般性的 trace ID、组件联动或状态观察作为从零创新。

新增建议是 AI 语义的调查契约：把能力输入、预处理版本、模型身份、有效工具集、输出 schema、异步结果归属和 UI 断言纳入同一样本。是否能通过现有接口实现这些关联、有哪些版本限制，需要工程验证。

## 7. 两个需要明确的验证边界

旧请求覆盖新界面的 A/B 图像案例为本报告构造场景，用来证明 ArkTS/ArkUI 的必要性，不是声称在 Apple 或鸿蒙发现了该产品缺陷。交互仅切换三种预先定义的调查状态，不会执行模型或真实采集。

固定输出重放用于隔离状态和界面问题；重新运行模型用于比较模型与配置质量。前者不能证明模型质量，后者不能保证文本逐字可复现。外部 provider 只能根据其授权 API 保存可见证据；系统助手内部规划、模型中间张量等不在开发者默认权限内。
