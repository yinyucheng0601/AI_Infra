来源与前提
沿 buffer 访问、索引源和同步覆盖核对扫描候选，带着选中的证据继续调查。
连线来自 analyzer 的 coverage / dependency，不表示实测时间或硬件完成顺序。结构扫描与图分析分别记录；0 候选不证明无问题。


教程 · 同步证据核查
1 · 价值
把扫描候选连回访问对象、同步边、索引表达式和源码。图用于检视静态证据，设备故障与收益仍需独立验证。
2 · 使用
从核查按钮选择候选，核对 expected / actual 与图中覆盖关系。打开源码查看行号；编辑问题，复制上下文继续调查。切换“索引不同源 → 仅统一索引源 → 统一 region 表达式”比较重新扫描的结果。
使用 ai-infra-investigation 总 workflow，接入 ascendc-sync-audit 的两个 JSON 输出。
保留所有原始候选，连接源码、buffer access、dependency、sync edge 和 coverage。
基于下面选中证据提出可验证方案；先核对 API、条件路径和关联文件。
不把静态候选认定为设备故障，不修改目标源码。

3 · 扩展
用 run_scan.py 接入另一固定版本文件及可定位头文件，再重建页面。新 API、宏、模板和跨函数场景需要额外语义核查；缺少关系时保留空缺，不自行补线。
4 · 实现分工
CANNBot 两个脚本生成候选和图证据；本页适配层保留来源 ID 并建立选择。ai-infra-glyphs 的 MemRef 呈现源码 buffer 引用；证据工作台组织核查与交接；Spatial Systems UI 和共享控件层提供画布、浮层、教程与提示。
