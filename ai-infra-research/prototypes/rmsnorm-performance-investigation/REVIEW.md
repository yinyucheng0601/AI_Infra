### 源码与模型粒度

- gamma：flow_runtime.py:206–238 每个 copy_in 按输入张量大小记一次；full Kernel 在每个非空核加载 gamma（rms_norm_direct.asc:186–191）；split 在每行每块加载（255–286）。XL flow weight=65,536 B，split Kernel gamma 请求合计=134,217,728 B。这里是 GM→UB 请求量，不是 HBM 事务量，缓存影响需设备数据。
- UB：flow live 峰值为 2X+gamma+2Y；full Kernel 另含 rowFactor、RowBytes 对齐和 256 B scratch，split 是三个双缓冲队列与 288 B scratch。chunk=4096 时 split 分配 98,592 B，与模型的抽象 tile 使用 253,952 B 不同。
- 边界 H=12672：模型 253,440 B 可驻留；源码按 1024 B 对齐后 rowBytes=51,200 B，rowFactor=1，分配 256,256 B，超过 253,952 B。该边界是待验证的源码参数问题，不建议直接发起 full Kernel。
- VF：full flow 是一个聚合 VF，Kernel 运行 RstdVF 与 NormVF；split 的分块累加 Add、多个局部 ReduceSum 与 WorkToRstdVF 不被逐指令展开。静态符合性门禁不证明任意 Kernel 与模型一一对应。
- BF16：flow 与引擎支持，但本次直调 Kernel 使用 float；不声明已经核对 BF16 Kernel。
