CANNBot 接入：从核对映射到发现同步候选

接入 ascendc-sync-audit ↗，使用其结构扫描与数据流分析脚本。扫描固定版本的 Unpack 源码，结果随页面保存；浏览器内不会重新运行扫描器。

接入前现在增加的核查能力
开发者提出索引、地址或任务假设，再点选核对。结构扫描主动提出同步候选，包括提前退出可能跳过 Set，以及计算后搬出前可能缺少同步。
图中关联元素、Task、Core 与源码。增加搬入 → 同步 → 计算 → 同步 → 搬出的源码调用链，关联 buffer、执行流水与源码行，便于逐步核对候选。
复制当前对象，手动补充调查线索。候选绑定可达 shape 与 Task；点选后跳转，复制上下文同时携带扫描证据与当前选择。

本例实际结果：结构扫描给出 3 项候选，数据流分析没有新增候选。图中路径与 shape 的绑定由本项目适配器完成，扫描器本身不理解这些配置，也没有证明实际设备访问正确。

已用上游好例、坏例及本地修订样例验证扫描链路，并重新扫描比较结果。真实 Unpack 未修改，候选仍需核对控制流、同步 helper 与 API 语义；数据流分析采用正则前端，未报出问题不等于安全。下一步可带着选中证据提出最小修改，再重扫并补充设备验证。

候选复核：初始显示“待复核”。在“继续调查”点击“模拟复核”，展示已保存的 3 项源码复核结论与绿色“已排除”标签；此按钮不调用 agent、不重跑扫描器。随后点选候选可查看逐段源码依据与仍需的设备证据；原始扫描消息完整保留。复核对象携带源码版本与哈希，并随“复制上下文”导出。新候选默认“待复核”；依据不足时应记录“仍需验证”，不能为了清空列表而排除。
