# AI Infra 可控 Pattern 接口实施计划

此文档维护 Pattern 接口的实施细节。总体职责、共享语义和阶段门槛见 [总体架构计划](ai-infra-skill-architecture-plan.md)。

## 目标与边界

让开发者调用 ai-infra-investigation 时，可以明确指定页面布局、完整 Pattern 和必须启用的组件。把可执行的约束交给实际渲染入口和校验，而不是要求 Agent 每次照着描述重写页面。

本计划供独立对话执行。本轮先做一个可运行闭环，再验证第二个消费者。保持总 Workflow 的五步和呈现契约职责。接口消费呈现契约和调用约束。领域分析、工具调度及宿主执行按总体计划的边界处理。

## 接口分层

| 接口 | 固定约束 | 允许配置 |
|---|---|---|
| 工作台布局 | 主舞台、工具栏、检查区域；打开浮层不挤压主画布；并排退出恢复原视角 | 宿主允许的布局模式及插槽内容 |
| 完整计算图 Pattern | 节点与端口语义、端点推导、选择、定位、导航与适配规则 | 图数据、分组、展开权限和初始对象 |
| 完整泳道图 Pattern | 泳道、事件／步骤、选择联动、尺度与视口 | 分组、来源、轴模式。真实时间需有时间来源及单位，源码步骤轴不显示实测耗时或暗示并发 |
| 核查面板 | 当前对象、证据、适用条件和缺口。候选复核才启用对应状态 | 可见依据、操作、发起上下文和结果更新条件 |
| 缩放控件 | 缩放、适配、复位与定位的统一语义；选择与视口分别管理 | 初始视角、缩放范围及多视图联动 |
| 播放条 | 播放、暂停、跳步、结束及切换后的状态规则 | 步骤播放或时间播放、可回放范围。真实时间播放需有带单位的时间数据 |

用一个带版本的调用声明同时驱动校验和挂载。优先沿用现有 Pattern 的 schema、事件与生命周期，先用一个轻量实现。以下是目标调用形态，待与真实 Pattern 能力对齐：

```yaml
version: 1
pattern: swimlane
layout: investigation-workbench
axis: source-step
controls:
  zoom: required
  inspector: required
  playback: optional
```

呈现契约另外提供对象 ID、定位目标、证据引用、动作上下文和更新条件。组件读取同一身份与关系数据，选择状态与视口状态分离。必选能力缺输入、Pattern 不支持某项能力、引用无法解析时，校验必须指出具体字段及下一步。可选能力缺输入时，按任务省略控件或显示明确的不可用状态。避免悄悄换布局、换轴或补造数据。

## 声明、实现与验证分开记录

- **资产信息**沿用 catalog、既有 manifest 和来源记录。首例从现有资产 ID、版本或固定 revision、真实挂载入口，以及实际调用所需的输入说明开始。保留现有正式 Glyph Library 及 renderer 来源。
- **调用匹配**由实现阶段使用。对照共享语义数据与调用约束，记录支持的对象／关系、必选与可选输入、轴／尺度、适用模式、控件和不支持能力。只为首个消费者真正使用的字段加机器校验；已有等价声明直接沿用。
- **事件与状态**只暴露首例所需的选择、定位或视口操作；筛选、动作、播放及销毁按资产实际行为验证。共享对象引用和证据来自呈现契约。组件事件传递明确对象，选择与视口独立；返回归档遵循总体计划的 Action / Result 规则。
- **能力证据**记录哪份数据、哪次挂载、哪个操作通过。manifest 的声明不等于已实现。目录只负责发现，实例脚本与产品验收负责证明可用，未验证能力明确标出。
- **维护方式**不建立额外 Pattern／Glyph Registry、通用组件框架或 Adapter 平台。Markdown 能指导调用时保留说明；出现实际机器消费时扩展最接近的现有资产声明，并用现有脚本校验。

## 分阶段实施

1. **先做一个纵向闭环。** 在检查后确定一个已有完整 Pattern，优先选择已有稳定对象 ID 和证据绑定的计算图或泳道。接上工作台布局、共享选择与视口、核查面板、缩放控件和一条可调用入口。用一个现有案例声明、挂载、验证。至少一次用通过共享语义检查的数据实际挂载；在总体计划迁移 Skill 职责前完成。若用 `sync-1`，沿用固定版本的候选及证据，预设复核明确标为回放。
2. **用第二个消费者检验复用。** 接入另一个真实配置或第二类 Pattern。确认只需更换模型或适配层，不需复制骨架和控件。公共边界以两次接入的实际差异为准。
3. **再接播放条。** 选有真实步骤或时间输入的消费者，明确播放模式与中断规则。加必选能力和轴口径的反例验证。完成后记录已支持的声明字段、资产入口以及未支持能力。
4. **接回 Skill 调用。** 实现和验收通过后，把可用接口、适用前提与失败处理交给总 Workflow 的「选择并实现界面」阶段维护。是否同步改 Skill 或分发包由执行对话按实际交付范围确认。

## 验收与交付

- 在默认视图找到目标 → 点选图上对象 → 面板显示同一 ID 的证据 → 核对固定来源 → 关闭面板。选择和视角保持，fit、复位和缩放可用。
- 缺字段、错误的证据引用、缺播放输入的必选配置，以及向源码步骤轴提供不合适的时间能力，均有明确反馈。检查边和端点随模型变化正确更新。
- 有比较视图时验证进入和退出后的视角恢复。有播放时验证播放、暂停、跳步、结束及切换后的状态。
- 第二个配置或消费者使用同一接口，记录确实复用的资产和行为。没有第二例前，交付声明限定于首个已验证案例。
- 按仓库规则核对单一 hover/focus 提示、选中填充和可读布局。分别记录静态／脚本检查、用户确认的浏览器效果和未验证项，遵循项目的浏览器验收约束。
- 提交给评审的材料包括调用声明与一份示例、实际源码及可打开的预览、首例与第二例验证记录、已知限制。若修改已收录 Pattern，使用已有构建和目录校验。

## 新对话起步指令

> 读取本计划，先核对仓库约束和现有 Pattern，完成第一阶段的最小闭环。选定一个已有可复用的 Pattern，建立可校验调用声明，接通点选、核查、关闭面板和视角保持。用真实现有案例验证。把第二消费者和播放条按各自前提推进，避免顺手重写总 Workflow。
