前面的三钻说明了人与 Agent 如何共同调查，三个案例分别展示了时间关系、跨层结构和参数影响的交互表达。要让这些体验能够复用，我们将设计判断沉淀为资产和 Skill，嵌入工程 Harness 的调查过程。

这些资产沉淀下来的，不只是图形样式，也包括什么问题适合什么表达、哪些关系必须保留，以及生成之后应该检查什么。Design Skill 将这些设计判断串成可执行的规则：根据当前问题和证据，选择已有图元、Pattern 和交互框架，组装视图，再核查语义、对象绑定和来源。

这里需要区分两层职责。工程 Harness 负责推进调查，Design Skill 负责组织视觉表达。它们贯穿 Focus、Uncover 和 Intervene，持续支撑三钻协同。开发者通过视图发现问题、调整条件或提出新的证据要求，再将上下文交回 Harness；新的证据回来后，又可以触发视图更新。

下面依次看这些设计资产，以及 Skill 如何把它们组织起来。

先看图元。模型、张量、内存和计算单元这些对象，需要有相对稳定的视觉表达。这样换一个场景，开发者仍然能认出它们，Agent 生成的时候也有共同的规则。

再看 Pattern。比如刚才的执行泳道、模型层级和参数联动，它们分别适合表达时间关系、层级关系和计算影响。这里把适用问题、对象关系和交互方式一起整理下来，方便按任务选择。

然后是页面框架。主体画布留给当前要理解的对象，场景切换、阶段导航和视野控制放在周围，细节在需要时原位展开。这样既保留操作入口，也能给复杂关系留下足够的展示空间。

这里再用一个内存案例，看看这些设计怎么组合起来。

画布展示了四路绑定指向同一个内存地址，开发者可以选中对象，对照相关记录。但共用地址是否造成覆盖，还要继续检查它们各自的写入、读取和生命周期。所以核查面板会把已有记录，以及还需要补充的问题放在一起，方便继续调查。

这也对应了 Skill 的工作流程。先明确工程问题和现有证据，再决定需要表达什么关系，组合已有的图元、Pattern 和框架，最后核查对象绑定、交互和来源。

工程 Harness 决定需要调查什么、调用什么工具，以及何时执行验证。Design Skill 决定当前证据应该采用什么视觉表达，如何复用图元和 Pattern，以及怎样核查生成结果。

开发者在视图中发现问题、调整条件或提出新的证据要求，可以把这些上下文交回工程 Harness。Harness 获得新的证据后，又可能触发视图更新。两层闭环相互衔接，让调查和表达随着证据持续推进。
