<!--
想象一根下载进度条，你脑中这个进度条是很顺利地加载完了，还是卡在某个点不动了？

我们作为 C 端用户，看到进度条卡住都很习以为常了。是不是网络不好？或者这个进度条是不是“骗人的”？

计算领域的开发者，其实也会面对这样一根进度条。一个计算任务跑到哪里了，为什么这里特别慢？但这根进度条背后，需要打开的黑盒就多得多了。我初步归纳了三个方面。

领域知识。 不管是在开发一个小算子，还是让一个 DeepSeek 这样的大模型跑起来，背后都涉及大量专业知识。过去，开发者主要凭经验把这些知识关联起来，才能理解眼前发生了什么。如今，开发者可以依赖 Agent 来补充和关联知识，帮助理解复杂计算问题。

计算机制。 同样是“这里耗时特别长”，究竟是在等内存数据搬运，还是存在资源争用？这就涉及硬件约束，需要结合证据进一步判断。

人的认知。 你认为开发者更想看到的是一根进度条，还是成千上万条时序记录？只看进度条，可能解释不了问题。把所有数据展开，他也很难一下找到重点。开发者本身就面对海量数据，注意力非常宝贵，所以我们也需要把 C 端设计中关于认知负荷、信息层级和反馈的经验带进来，约束视觉展示什么。

Agent 的工程能力。 在今天这个 AI 时代，开发者看到任务卡住，第一反应可能是派一个 Agent 去调查。但 Agent 需要具备领域知识、工具调用、证据管理和执行验证能力，才能将开发者的问题转化为持续推进的调查任务。

我们的设计工作建立在这些工程能力之上，结合前面三个方面，重点研究如何把 Agent 组织的复杂证据，转化为开发者能够理解、核查和介入的交互体验，帮助他依据证据作出决策。
