# 汇报主线：发现问题 → 看懂证据 → 介入纠正

首页既有卡片保留设计，只调整顺序：问题／结果驱动（浅紫）→ 认知减负（蓝紫）→ 有效控制（黄绿）。

## 主案例

1. 执行泳道：问题／结果驱动。由性能症状触发相关时间关系与原始事件。
2. Layer Stack：认知减负。把跨层查找变成同一对象的连续证据。
3. Scale：有效控制。在决策检查点核查依据、调整参数、保留上下文。

## 抽象与沉淀

4. 页面框架：问题／结果驱动。组合主视图、关联视图和验证信息。
5. 体系复用：有效控制。证据契约约束允许结论，P0–P2 定义演进，H1–H4 检验价值。

## 推导关系

### 从性能症状，推导需要展开的执行证据

对应原则：问题 / 结果驱动

框架：问题触发可视化

设计机会：按诊断问题筛选证据，再展开执行关系

| 判断困难 | 设计响应 |
|---|---|
| 只知道总耗时变长 | 共享时间轴：直接比较阶段关系 |
| 日志难比较重叠与等待 | 泳道聚焦：突出与问题相关的事件 |
| 事件太多，难找到相关范围 | 原始事件：为候选原因保留核查入口 |

现有设计支持时间比较、泳道聚焦与原始事件核查；自动诊断与生成视图属于演进目标。

### 从跨层查找，推导连续的对象与证据关系

对应原则：认知减负

框架：降低信息关联成本

设计机会：让层、节点与采样共享同一调查上下文

| 判断困难 | 设计响应 |
|---|---|
| 从模型到层，重新找位置 | 连续画布：保留层序和当前位置 |
| 从层到节点，重新找对应 | 局部展开：沿当前层进入计算节点 |
| 从节点到采样，重新建上下文 | 身份携带：定位到同一对象的采样 |

降低关联成本是待验证的设计假设；层序、节点与采样关联是当前设计机制，采样不等于设备观测。

### 从介入困难，推导可操作的决策检查点

对应原则：有效控制

框架：Decision Checkpoint

设计机会：把检查、调整与继续放在同一对象上下文中

| 判断困难 | 设计响应 |
|---|---|
| 看到结论，难以检查依据 | 计算依据：检验当前参数解释 |
| 调整参数，难以看清影响 | 联动高亮：检查参数影响的输出 |
| 完成核查，容易丢失调查条件 | 上下文保留：携带对象与配置继续 |

参数交互、计算依据与上下文保留为当前设计；Agent—人—Agent 的自动反馈闭环为目标工作流。

### 从证据分散，推导问题定向的视图组合

对应原则：问题 / 结果驱动

框架：Diagnostic View Composition

设计机会：主视图、关联视图、验证视图共享对象与证据引用

| 判断困难 | 设计响应 |
|---|---|
| 结果、关系、验证各自独立 | 任务分组：明确当前查什么 |
| 切换视图后要重新选对象 | 视角与导航：同一对象换观察方式 |
| 细节常驻，主体被持续挤占 | 按需检查：只展开当前选择的细节 |

视图组合是设计目标；当前框架演示对象身份、任务、视角、导航与检查职责，未宣称接通全部工具。

### 从输出失控，推导可复用的证据与验证约束

对应原则：有效控制

框架：Evidence Contract

设计机会：共用证据 → 专用视图 → 控制与恢复

| 判断困难 | 设计响应 |
|---|---|
| 样式复用后，语义仍可能漂移 | 图元 / Pattern：固定语义与联动契约 |
| 证据不足，结论却越过边界 | Skill：声明最低证据、缺失项、停止条件 |
| 界面通过自检，收益仍未知 | H1–H4：用真实任务对照检验增量价值 |

图元、Pattern 与 Skill 是当前基础；P0–P2 是能力演进框架，H1–H4 是待验证假设。
